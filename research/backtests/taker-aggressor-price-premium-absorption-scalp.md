# [단타 15m/1h] 테이커 매수/매도 평균체결가 프리미엄 급변 흡수 리버설 스캘프 — 백테스트 리포트

- **스펙**: `research/strategies/taker-aggressor-price-premium-absorption-scalp.md`
- **구현**: `research/impl/taker_aggressor_price_premium_absorption_scalp.py`
  (공통 로더: `research/impl/bt_common.py`)
- **검증일(UTC)**: 2026-08-13

## 1. 방법 / 재현성

- **데이터**: `data.binance.vision` 선물(um) 15m klines 월별 덤프(fapi 451 차단 대응).
  `taker_buy_volume`(base)·`taker_buy_quote_volume`(quote)·`quote_volume`·`volume`·`count`
  전 필드 사용(표준 캐시엔 OHLCV 5개만 남아 있어, 캐시 pickle 재사용하되 전체 컬럼을 보존하는
  `load_klines_full()`을 별도 구현).
- **유니버스**: BTC/ETH/BNB/SOL/XRP/DOGE/ADA(7종목, 전부 major_bases → 레버리지 30x).
- **기간**: IS 2022-01-01~2024-06-30 23:59:59 / OOS 2024-07-01 00:00:00~2026-06-30 23:59:59.
  IS_END 를 23:59:59 로 명시(경계일 장중 진입 누락 방지), 모든 entry_time 필터에 상한 적용.
  **IS+OOS == FULL 실측**: IS 3,351 + OOS 2,761 = 6,112 = FULL(전체 df) 6,112건 — 정합 확인.
- **비용**: 편도 테이커 0.05% + 슬리피지 0.02%(왕복 0.14%), 체결가 `open[t+1]×(1±slippage)`.
- **사이징**: `RiskManager.build_plan_with_stop` 재현 — `risk_amount = equity×1%`(`risk_per_trade_pct`),
  레버리지 상한 클램프 시 `risk_amount` 도 동일 비율로 축소(코드: `risk_manager.py` L169-207).
- **핵심 신호 정의**(스펙 그대로):
  `buyer_avg = taker_buy_quote_volume/taker_buy_volume`,
  `seller_avg = (quote_volume-taker_buy_quote_volume)/(volume-taker_buy_volume)`,
  `premium_bps = (buyer_avg-seller_avg)/close*10000`,
  `premium_z` = 최근 100봉(자기 포함, 코드베이스 `bollinger_bands` 관례와 동일 — bar t 는 이미
  닫힌 봉이라 룩어헤드 아님) 롤링 평균/표준편차로 정규화,
  `body_ratio = |close-open|/(high-low)`.
  숏: `premium_z>=+2.5 AND body_ratio<=0.35`. 롱: `premium_z<=-2.5 AND body_ratio<=0.35`.
  1h 확인: 1h EMA20 슬로프(완결봉만 참조, `shift(1)`+시간버킷 reindex 로 인과성 확보)가
  진입 방향과 뚜렷이(`|slope|>=0.5%`) 반대면 스킵.
- **청산**(스펙 원문이 다소 모호해 다음과 같이 [설계값] 확정, 리포트 상단 docstring에 명시):
  손절폭 = `min(신호봉 반대극값 거리, ATR(14,15m)×1.0)`("더 타이트한 쪽"), 최종방향 기준
  진입가 대칭 배치. 매 봉 "이전 봉까지 갱신된 스톱"으로 먼저 히트 체크(손절 우선) →
  히트 없으면 이번 봉 유리한 극값으로 트레일링 후보(`run_ext∓ATR×1.6`) 계산해 스톱을
  **단조 타이트닝만** 허용(동봉 룩어헤드 방지, `SleeveBacktester.momentum_trail` 과 동일 순서).
  TP 는 진입가 대비 `R:R=1.4` 고정. `max_hold=12봉(3h)` 초과 시 종가 시간청산.

## 8. de-clustering / R-배수 재계산

### 동시진입일 비율(OOS)

명목 거래 2,761건 → 고유 진입일 667일(동시진입 종목수 분포: 1종목 121일 · 2종목 151일 ·
3종목 137일 · 4종목 120일 · 5종목 80일 · 6종목 43일 · 7종목 15일). 상당한 클러스터링이 있어
de-clustering으로 t 를 재계산했다.

| 집계 단위 | n | t-stat |
|---|---:|---:|
| 명목(거래단위) | 2,761 | -15.63 |
| 일단위 합산 R | 667 | -22.46 |
| 주단위 합산 R | 105 | -20.74 |

de-clustering 후에도 t 가 **오히려 더 극단적**(일/주 단위 합산에서 손실이 더 일관되게
나타남) — 명목 t 가 의사반복으로 부풀려진 것이 아니라, 진짜로 구조적인 음의 기댓값임을
재확인.

**[리뷰어 정정, 2026-08-13]**: 이 비교는 **단위가 섞여 있다** — "명목(거래단위) t=-15.63"은
달러 손익(`pnl`) 기준인데 "일단위 t=-22.46"·"주단위 t=-20.74"는 R-배수(`pnl/risk_dollar`)
기준이라 직접 비교가 성립하지 않는다(리뷰어가 `bt_common`/구현 코드를 그대로 써서 독립 스크립트로
단위를 통일해 재계산: 달러 기준 trade-level -15.63 → 일단위 -13.07 → 주단위 -9.91 로 **정상적으로
감쇠**하고, R-배수 기준으로도 trade-level -29.60 → 일단위 -22.46 → 주단위 -20.74 로 **동일하게
감쇠**한다 — 이것이 de-clustering의 통상적인 방향이다. 원문의 "오히려 더 극단적"이라는 서술은

과제에서 지적한 대로 "일/주단위 t가 명목보다 더 극단적"이라는 방향이 통계적으로 이례적이어서
직접 파고들었다. **원인은 단위 혼용**이다: 리포트의 "명목(거래단위) t=-15.63"은 달러 손익
기준인데 "일단위 -22.46"·"주단위 -20.74"는 R-배수 기준이라 애초에 비교 기준이 다르다. 독립
스크립트로 단위를 통일해 재계산한 결과:
- 달러 기준: 거래단위 -15.63 → 일단위 -13.07 → 주단위 -9.91 (정상적으로 감쇠)
- R-배수 기준: 거래단위 -29.60 → 일단위 -22.46 → 주단위 -20.74 (정상적으로 감쇠)

두 경우 모두 **de-clustering이 정상 방향(t 완화)으로 작동**했다 — 원문의 "오히려 더 극단적"은
단위 혼용에서 비롯된 서술 오류이며, 본문 §8에 `[리뷰어 정정]`으로 반영했다. 다만 **결론은
불변**: 가장 보수적으로 잡아도(달러·주단위, n=105) t=-9.91 로 압도적으로 유의해, 의사반복이
결과를 만들어낸 것이 아니라는 원 결론 자체는 오히려 더 굳건해진다.
