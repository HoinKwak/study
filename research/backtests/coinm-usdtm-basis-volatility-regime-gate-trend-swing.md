## 판정: **판단불가 (Indeterminate)** — 스펙 자신의 사전 폐기조건①에 정확히 해당

스펙 「사전 폐기조건」은 세 가지 중 하나라도 걸리면 폐기하되, **"OOS n < 15"는 명시적으로 FAIL이
아니라 "판단불가"로 분류**하라고 못박고 있다. 실측 **OOS n=11**(<15)로 이 조건이 그대로
트리거된다. 사전에 정한 이 매핑을 사후에 다른 기준(예: n=20 통과 임계)으로 바꾸지 않고 그대로
적용해 **판단불가**로 판정한다.

다만 표본이 얇아 확정적 결론은 못 내리지만, **방향성 증거는 모두 게이트가 부가가치를 만들지
못하거나 오히려 해가 되는 쪽을 가리킨다**(아래 §4 핵심 대조군 참고) — "판단불가이지만 낙관적인
판단불가"가 아니라 "판단불가이며 현재까지의 정황은 FAIL 쪽에 가깝다"는 점을 정직히 기록한다.
**라이브에는 반영하지 않는다.**

## 0. pandas/시간축 함정 점검(과제 지시 사항)

- **UM/CM markPriceKlines 병합**: `open_time`(ms epoch int) → `pd.to_datetime(unit="ms")` →
  `.astype("datetime64[ns]")` 로 명시 통일(기존 여러 라운드가 경고한 ms→us 업캐스트 함정 회피
  경로). 4h→1d 정렬은 `Timedelta` 덧셈을 전혀 쓰지 않고 **`.floor("D")` + `groupby.last()`만
  사용**(하루가 정확히 4h봉 6개[00/04/08/12/16/20]로 나뉘고, 20:00봉의 종료시각이 정확히
  다음날 00:00=그 일봉의 종료시각과 일치하므로 이 방법이 룩어헤드 없이 정렬 가능함을 이용).
- **회계정합**: `max|raw_pnl - fees - pnl| = 0.0`(21건 전수, §1).
- `bool.shift(1).fillna(False)` object-dtype 함정: 이 코드는 크로스 이벤트를 `(close>ema)&(close.
  shift(1)<=ema.shift(1))` 형태의 불리언 논리곱으로만 계산하고 별도 object-dtype 경유가 없어
  해당 없음.

## 3. 전제의 내적 일관성 — 베이시스변동성 vs BTC 가격 realized vol 상관

스펙 자신의 사전 폐기조건③(|r|>=0.5 이면 "독립정보 아님"으로 FAIL)을 점검:

```
corr(pctile_vol, price_vol_pctile) [일봉정렬, IS+OOS]: 0.275
corr(basis_vol, price_vol) [레벨, IS+OOS]           : 0.369
corr(pctile_vol, pctile_level) [변동성게이트 vs 레벨게이트]: -0.082
```

**|r|=0.275~0.369 < 0.5 — 이 폐기조건은 트리거되지 않는다.** 베이시스 변동성 게이트는 BTC
가격 자체의 realized vol을 단순 재포장한 것이 아니라(과거 여러 라운드에서 반복 발견된 재포장
함정과 다름), 독립적인 정보를 담고 있다는 스펙의 전제가 실측으로 뒷받침된다. 또한 변동성 게이트
(`pctile_vol`)와 레벨 게이트(`pctile_level`)의 상관도 거의 0(-0.082)이라, 둘은 서로 다른
성질의 게이트임이 확인된다(§4의 비교를 정당화).

**요약: 폐기조건①(OOS n<15)만 트리거, 폐기조건③(상관 재포장)은 트리거되지 않음.**

## 4. ⭐ 핵심 대조군 — 게이트가 부가가치를 만드는가

② no_gate(게이트 없음, 순수 EMA50)         OOS n=24 PF_gross=1.325 PF_net=1.281 t=+0.510
③ level_gate(베이시스 레벨 게이트, 스펙 배제안) OOS n=14 PF_gross=1.394 PF_net=1.310 t=+0.338
```

FULL/IS 구간도 함께:

```

② no_gate: FULL n=57 PF_net=1.473(t=+1.16) | IS n=33 PF_net=1.661(t=+1.09)

**게이트 없는 순수 EMA50 추세추종(②)과, 스펙이 이론적으로 배제한 베이시스 레벨 게이트(③)가

대조군보다 오히려 나쁘다" 패턴과 일치한다. `zero_hold_frac`은 base/no_gate/level 모두 0/n으로
정상(청산로직 버그로 인한 인공적 결과가 아님).

### 정보원 무력화 대조군 — 게이트 값 블록셔플(100회, 30일 블록)

셔플 대상은 **가격 레벨이 아니라 `pctile_basis_vol`(0~100 유계 백분위 시리즈)**이다 — 과제
지시 사항("블록셔플은 수익률 단위로, 가격 레벨 셔플은 인공 갭 생성")이 우려하는 문제는 누적
가격 경로를 임의 재배열할 때 발생하는데, 백분위 랭크는 이미 정상화·유계된 값이라 블록을
재배열해도 인공적인 갭이 생기지 않는다(거래되는 실제 BTC 가격 경로는 전혀 건드리지 않고
게이트가 "언제 열리는가"의 타이밍만 무작위화).

```
base OOS n=11 PF_net=0.6815
셔플 100회(block=30일): PF_net 중앙값=1.114 (평균은 소표본 극단치로 왜곡돼 참고만: 15.62)
n평균=8.0
base PF가 셔플분포에서 차지하는 백분위: 26.0%
base net_pnl(=-118.2)이 셔플 net_pnl 분포에서 차지하는 백분위(더 강건): 25.0%
```

⚠️ **PF는 각 셔플 반복의 표본이 3~15건으로 극히 작아, 손실거래가 우연히 1건뿐이면 분모가
0에 가까워지며 PF가 수백~수천대로 튀는 경우가 발생**(평균 15.62·표준편차 109는 이 극단치에
전적으로 좌우된 값이라 z-검정에 부적합 — 중앙값과 net_pnl 백분위를 대신 사용). **실제(base)가
셔플 분포의 하위 25~26%에 위치** — 임의로 섞은 타이밍이 실제 데이터 타이밍보다 더 나은 경우가
100회 중 약 75회다. n이 작아 통계적으로 강한 결론은 못 내리지만(단측 p≈0.25~0.26로 5%
유의수준에 크게 못 미침), 방향은 §4의 다른 증거들과 일관되게 부정적이다.

- **룩어헤드**: 엔진을 쓰지 않고 (1) EMA50을 numpy로 직접 재구현(라이브러리 미사용, alpha=2/51
  루프)해 엔진 산출값과 전 구간 완전 일치(`max|diff|=0.0`) 확인 (2) `pctile_basis_vol`을 pandas
  `rolling().rank()` 대신 numpy 이중루프(`(seg<=val).sum()/len(seg)*100`)로 독립 재계산해
  2023-03-13 20:00 4h봉 값(96.667%)이 엔진의 일봉 정렬값과 일치 확인 (3) 실제 트레이드 #2
  (2023-03-14 롱 진입, entry_price=24124.3239)를 원본 1d klines로 역산 — 신호 확정일(2023-03-13
  종가, EMA50 상향돌파+게이트 96.67%>=75%) → 익일(2023-03-14) 시가(24119.5)×(1+슬리피지 0.0002)
  =24124.3239로 정확히 일치. 3개 지점 모두 독립 경로로 룩어헤드 없음을 직접 확증(리포트가 이미
  제시한 3-cut 절단 재실행도 재현 — 전부 `불일치 n=0`).
- **데이터소스**: `data.binance.vision`의 `markPriceKlines`(4h, UM/CM 둘 다) 2021-01 월분을
  직접 curl로 재확인 — **200 OK**(리포트가 `fundingRate`는 2022-07 이전 404, `markPriceKlines`는
  2021-01부터 가용이라 구분한 주장을 재확인. 참고로 `fundingRate` 2022-01·2022-06은 직접
  curl로 404 재확인해 과거 라운드의 "COIN-M 2022-07 이전 결측" 서술이 `fundingRate` 한정임도
  교차 검증). 실제 CM 4h 덤프(2023-03) 내용도 열어 확인 — 정상 BTC 가격대(약 $23,000~24,000),
  행수 186(31일×6봉) 일치.
- **단위(ns/us)**: um4·cm4·d1·basis4·gd·sig·gate_daily **인덱스 전부 `datetime64[ns]`**로 직접
  `dtype` 조회해 확인(pandas 3.0.5 환경에서 실행 — 과거 라운드의 `us` 업캐스트 함정이 재발하지
  않았음을 실측 확인). `Timedelta` 덧셈 없이 `.floor("D")+groupby.last()`만 쓴다는 코드 주장도
  실제 소스에서 확인.
- **게이트 발화율**: NaN 워밍업 구간이 `>=75` 비교에서 항상 False로 안전 처리됨(직접
  `pd.Series([nan,80])>=75` 테스트로 확인, 워밍업 오염으로 게이트가 우연히 열리는 결함 없음).
- **결측 4h봉 재계산(리포트 오류 발견)**: 전체 4h 그리드 대비 `Index.difference`로 직접 재계산한
  결과 리포트 본문의 "UM 24개·CM 54개"가 **뒤바뀌어 있고 날짜도 일부 누락**돼 있음을 확인
  (실제: UM 54개/9일, CM 24개/4일 — 본문 해당 위치에 취소선 정정 삽입). **다만 이 결측은 inner
  join으로 자연 제외되므로 핵심 수치(PF·거래수·회계정합)에는 영향 없음** — 결측 보정 전후로
  재실행한 sanity 수치가 동일함을 위 재현으로 확인.
- **`zero_hold_frac` 지표의 구조적 한계(리포트 서술 정정)**: `run_engine`의 포지션 관리 블록이
  `i > position.entry_idx`로 가드돼 있어 **이 엔진에서는 zero_hold_frac이 코드 구조상 항상
  0이 될 수밖에 없다** — 즉 "0/21이라 반전모드 원신호참조 버그가 없다"는 논리는 이 엔진에는
  적용되지 않는(항상 참이 되는) 트리비얼한 지표다. 다만 리뷰어가 별도로 소스코드를 직접 읽어
  포지션 관리·청산 분기가 전부 `Trade.direction`(최종 확정 방향)만 참조하고 원신호 플래그를
  전혀 참조하지 않음을 확인했으므로, **결론(해당 버그 없음)은 여전히 유효**하나 근거를
  zero_hold_frac이 아니라 코드 정독으로 교체해야 정확하다(본문에 취소선 정정 삽입).

### 최우선 검증 질문 답변

1. **표본이 얇은 이유 — 설계상 필연, 구현결함 아님**: EMA50 크로스 104건(23.15/년, 스펙 예상
   15~30/년), 게이트통과 21건(4.67/년, 스펙 예상 4~10/년) — 둘 다 직접 재실행으로 재확인했고
   스펙 예상 범위 안에 정확히 든다. 표본 얇음은 "BTC 단일종목×저빈도 게이트"라는 스펙 설계의
   필연적 결과이며, 구현 과정에서 신호가 부당하게 걸러진 증거는 발견하지 못했다.
2. **COIN-M 데이터 범위**: 과제 프롬프트가 언급한 "2022-07 이전 404"는 `fundingRate` 덤프
   얘기이고, 이 스펙이 실제로 쓰는 `markPriceKlines`는 2021-01부터 가용함을 직접 curl로
   재확인했다 — 리포트의 구분이 정확하다. IS_START는 스펙 원안(2022-01-01) 그대로 쓰였고 이로
   인한 IS 추가 축소는 없다.
3. **R-배수 재계산의 실재 여부**: 리포트가 제시한 3개 대조군의 R-배수 수치를 독립 스크립트로
   재현해 정확히 일치함을 확인했다(위 참고). 빈도가 다른 대조군(n=11 vs 24 vs 14) 비교에 달러
   PF만이 아니라 R-배수까지 병기한 파이프라인 규칙이 실제로 지켜졌다.
4. **셔플 대조군 설계**: 셔플 대상은 `pctile_basis_vol`(이미 0~100 유계 백분위)이지 BTC 가격
   레벨이 아니다 — 거래되는 실제 가격 경로는 전혀 건드리지 않고 "게이트가 언제 열리는가"의
   타이밍만 재배열하므로, 과거 발견된 "가격 레벨 블록셔플의 인공 갭" 문제 부류와는 다른 성격이라는
   리포트의 논증에 동의한다. 코드(`cmd_shuffle`)도 이 설명과 일치한다.
5. **'하위 25~26 백분위'의 해석**: 리포트가 스스로 "단측 p≈0.25~0.26로 5% 유의수준에 크게
   못 미침"이라 명시하며 이를 **단독 근거가 아니라 다른 방향성 증거들과의 일관성 확인용**으로만
   쓰고 있어, 과장이 아니라 적절히 헤지된 서술이다.

### 최종 의견: **판단불가(Indeterminate) 유지에 동의**

스펙의 사전 폐기조건①("OOS n<15 → FAIL 아닌 판단불가로 분류")이 실측 OOS n=11로 정확히
트리거됐고, 리포트가 이를 사후에 다른 기준으로 바꾸지 않고 그대로 적용한 것은 이 파이프라인이
최근 라운드에서 반복 강조한 "사전 폐기조건은 사후 변경 금지" 원칙에 부합한다. 방향성 증거
(게이트 있음 vs 없음 대조군 열세, R-배수로도 동일 방향, 부트스트랩 30.2%, 셔플 백분위 25~26%,
무비용 진단도 OOS<1, 파라미터 스윕 12변형 전부 미달)는 전부 리뷰어가 직접 재실행해 일치를
확인했고, 전부 게이트의 부가가치를 지지하지 않는 방향으로 일관된다. "판단불가이며 정황은 FAIL
쪽"이라는 리포트의 자체 평가는 과장이 아니라 정확한 서술이다.

리포트 라벨(판단불가) · 라이브 미반영 결정에 **동의하며 뒤집지 않는다**. 발견한 결함(§0 결측
4h봉 UM/CM 카운트 뒤바뀜, `zero_hold_frac` 지표의 구조적 트리비얼함)은 본문에 취소선으로
정정했으나 **핵심 결론(PF·거래수·판정)에는 영향을 주지 않는 경미한 서술 오류**였다.

**재검증 필요 여부**: 재실행 불필요(모든 핵심 수치 일치 확인). 다만 리포트 자신이 제안한 대로
표본을 늘리려면 `th_gate`를 낮춰 빈도를 늘리는 재설계나 더 긴 역사 확보가 필요하며, 그 경우
이번 판단불가 판정은 재검증 대상이 된다.
