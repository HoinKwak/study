## 판정: **판단불가 (Indeterminate)** — 스펙 자신의 사전 폐기조건①에 정확히 해당

스펙 「사전 폐기조건」은 세 가지 중 하나라도 걸리면 폐기하되, **"OOS n < 15"는 명시적으로 FAIL이
아니라 "판단불가"로 분류**하라고 못박고 있다. 실측 **OOS n=11**(<15)로 이 조건이 그대로
트리거된다. 사전에 정한 이 매핑을 사후에 다른 기준(예: n=20 통과 임계)으로 바꾸지 않고 그대로
적용해 **판단불가**로 판정한다.

다만 표본이 얇아 확정적 결론은 못 내리지만, **방향성 증거는 모두 게이트가 부가가치를 만들지
못하거나 오히려 해가 되는 쪽을 가리킨다**(아래 §4 핵심 대조군 참고) — "판단불가이지만 낙관적인
판단불가"가 아니라 "판단불가이며 현재까지의 정황은 FAIL 쪽에 가깝다"는 점을 정직히 기록한다.
**라이브에는 반영하지 않는다.**

## 0. pandas/시간축 함정 점검(과제 지시 사항)

- **UM/CM markPriceKlines 병합**: `open_time`(ms epoch int) → `pd.to_datetime(unit="ms")` →
  `.astype("datetime64[ns]")` 로 명시 통일(기존 여러 라운드가 경고한 ms→us 업캐스트 함정 회피
  경로). 4h→1d 정렬은 `Timedelta` 덧셈을 전혀 쓰지 않고 **`.floor("D")` + `groupby.last()`만
  사용**(하루가 정확히 4h봉 6개[00/04/08/12/16/20]로 나뉘고, 20:00봉의 종료시각이 정확히
  다음날 00:00=그 일봉의 종료시각과 일치하므로 이 방법이 룩어헤드 없이 정렬 가능함을 이용).
- **회계정합**: `max|raw_pnl - fees - pnl| = 0.0`(21건 전수, §1).
- `bool.shift(1).fillna(False)` object-dtype 함정: 이 코드는 크로스 이벤트를 `(close>ema)&(close.
  shift(1)<=ema.shift(1))` 형태의 불리언 논리곱으로만 계산하고 별도 object-dtype 경유가 없어
  해당 없음.

## 3. 전제의 내적 일관성 — 베이시스변동성 vs BTC 가격 realized vol 상관

스펙 자신의 사전 폐기조건③(|r|>=0.5 이면 "독립정보 아님"으로 FAIL)을 점검:

```
corr(pctile_vol, price_vol_pctile) [일봉정렬, IS+OOS]: 0.275
corr(basis_vol, price_vol) [레벨, IS+OOS]           : 0.369
corr(pctile_vol, pctile_level) [변동성게이트 vs 레벨게이트]: -0.082
```

**|r|=0.275~0.369 < 0.5 — 이 폐기조건은 트리거되지 않는다.** 베이시스 변동성 게이트는 BTC
가격 자체의 realized vol을 단순 재포장한 것이 아니라(과거 여러 라운드에서 반복 발견된 재포장
함정과 다름), 독립적인 정보를 담고 있다는 스펙의 전제가 실측으로 뒷받침된다. 또한 변동성 게이트
(`pctile_vol`)와 레벨 게이트(`pctile_level`)의 상관도 거의 0(-0.082)이라, 둘은 서로 다른
성질의 게이트임이 확인된다(§4의 비교를 정당화).

**요약: 폐기조건①(OOS n<15)만 트리거, 폐기조건③(상관 재포장)은 트리거되지 않음.**

② no_gate(게이트 없음, 순수 EMA50)         OOS n=24 PF_gross=1.325 PF_net=1.281 t=+0.510

FULL/IS 구간도 함께:

**게이트 없는 순수 EMA50 추세추종(②)과, 스펙이 이론적으로 배제한 베이시스 레벨 게이트(③)가

대조군보다 오히려 나쁘다" 패턴과 일치한다. `zero_hold_frac`은 base/no_gate/level 모두 0/n으로
정상(청산로직 버그로 인한 인공적 결과가 아님).

### R-배수(등가중) 재계산 — 복리 사이징 아티팩트 배제

```
base(등가중 R)    : OOS n=11 R_mean=-0.104 t=-0.519 PF[R]=0.688
no_gate(등가중 R) : OOS n=24 R_mean=+0.114 t=+0.527 PF[R]=1.292
level_gate(등가중 R): OOS n=14 R_mean=+0.074 t=+0.351 PF[R]=1.324
```

달러 PF와 R-배수 PF가 **동일 방향·거의 동일 크기**로 일치 — 복리 사이징이 결론을 왜곡한
아티팩트가 아니라 진짜 결과다.

### 대조군 우열 부트스트랩(표본수 맞춤, 과제 지시 사항)

```
base OOS n=11 PF=0.6815 | no_gate OOS n=24 PF=1.2813
부트스트랩(n=11 맞춤, 2,000회): base(게이트있음)가 no_gate보다 PF 높을 확률 = 30.2%
diff 분포: mean=-0.729 5%=-3.784 95%=+1.438
```

base가 no_gate를 능가할 확률이 **30.2%로 50% 미만**(diff 90% CI가 0을 포함해 통계적으로
"유의하게 나쁘다"까지는 아니나, 방향은 뚜렷이 부정적) — 스펙 사전 폐기조건②("게이트 있음 vs
게이트 없음 대조군 대비 개선이 부트스트랩 p>0.1로 비유의")에 **정확히 해당한다**. 다만 표본이
워낙 작아(n=11) 이 부트스트랩 자체의 검정력도 낮다는 한계를 함께 기록한다.

### 정보원 무력화 대조군 — 게이트 값 블록셔플(100회, 30일 블록)

셔플 대상은 **가격 레벨이 아니라 `pctile_basis_vol`(0~100 유계 백분위 시리즈)**이다 — 과제
지시 사항("블록셔플은 수익률 단위로, 가격 레벨 셔플은 인공 갭 생성")이 우려하는 문제는 누적
가격 경로를 임의 재배열할 때 발생하는데, 백분위 랭크는 이미 정상화·유계된 값이라 블록을
재배열해도 인공적인 갭이 생기지 않는다(거래되는 실제 BTC 가격 경로는 전혀 건드리지 않고
게이트가 "언제 열리는가"의 타이밍만 무작위화).

```
base OOS n=11 PF_net=0.6815
셔플 100회(block=30일): PF_net 중앙값=1.114 (평균은 소표본 극단치로 왜곡돼 참고만: 15.62)
n평균=8.0
base PF가 셔플분포에서 차지하는 백분위: 26.0%
base net_pnl(=-118.2)이 셔플 net_pnl 분포에서 차지하는 백분위(더 강건): 25.0%
```

⚠️ **PF는 각 셔플 반복의 표본이 3~15건으로 극히 작아, 손실거래가 우연히 1건뿐이면 분모가
0에 가까워지며 PF가 수백~수천대로 튀는 경우가 발생**(평균 15.62·표준편차 109는 이 극단치에
전적으로 좌우된 값이라 z-검정에 부적합 — 중앙값과 net_pnl 백분위를 대신 사용). **실제(base)가
셔플 분포의 하위 25~26%에 위치** — 임의로 섞은 타이밍이 실제 데이터 타이밍보다 더 나은 경우가
100회 중 약 75회다. n이 작아 통계적으로 강한 결론은 못 내리지만(단측 p≈0.25~0.26로 5%
유의수준에 크게 못 미침), 방향은 §4의 다른 증거들과 일관되게 부정적이다.

검증 임계 미달이라 서브모드 분리는 "더 얇은 판단불가"를 재확인하는 것 이상의 정보를 주지
못한다. 참고용으로만 기록한다.

## 6. 방향반전 대조군

`is_long = position.direction == "long"`(진입 시 확정된 최종 방향 변수)만 SL/TP·시간청산·
레짐해소청산 전 분기에서 참조하도록 구현(과거 여러 라운드에서 발견된 "원신호 플래그 재참조"
안티패턴 없음) — `zero_hold_frac` 정방향·반전 모두 **0/21**로 정상 확인.

```
정방향: FULL n=21 PF_net=1.153(t=+0.24) | OOS n=11 PF_net=0.681(t=-0.53)
반전  : FULL n=21 PF_net=0.891(t=-0.20) | OOS n=11 PF_net=0.796(t=-0.29)
```

**반전도 OOS PF_net<1**(0.796) — 정방향(0.681)보다 근소하게 낫지만 둘 다 1 미만이라
"방향을 뒤집으면 통한다"는 근거도 없다. EMA50 크로스 방향 자체가 이 게이트 조건 하에서는
뚜렷한 정보를 담고 있지 않다는 정황(정방향·반전 모두 무너짐)으로 해석한다.

## 11. 최종 판정: **판단불가 (Indeterminate)**

**근거**:

1. **스펙 사전 폐기조건①(OOS n<15)이 정확히 트리거됨**: 실측 OOS n=11. 스펙이 스스로 이 경우를
   "FAIL이 아니라 판단불가로 분류"하라고 명시했으므로 그대로 적용한다(사후에 임계값을 바꾸지
   않음).
2. **스펙 사전 폐기조건③(상관 |r|>=0.5)은 트리거되지 않음**: 베이시스변동성-가격변동성 상관
   0.275~0.369로 독립정보 요건을 통과했다 — 이 부분은 스펙의 설계 의도가 실측으로 지지된다.
3. **그럼에도 방향성 증거는 전부 부정적(스펙 폐기조건②와 정합)**: 게이트 없는 순수 EMA50(②)과
   스펙이 배제한 베이시스 레벨 게이트(③)가 OOS에서 채택 게이트보다 뚜렷이 우수하고(§4),
   표본수 맞춘 부트스트랩에서 채택 게이트가 no_gate를 이길 확률은 30.2%뿐이며(스펙 폐기조건②
   "p>0.1로 비유의"에 해당), 블록셔플 대조군에서도 실제 데이터가 하위 25~26 백분위에 위치한다.
   R-배수 재계산으로 복리 사이징 아티팩트도 배제했다.
4. **비용과 무관한 구조적 약세**: 무비용 진단(fee=0)에서도 OOS PF 0.739로 1 미만.
5. **파라미터 스윕 12변형 전부 검증 가능 표본(20건)에 못 미치고 PF가 0.325~1.796으로 요동** —
   안정적으로 통과 기준을 만족하는 조합이 없다.
6. **룩어헤드 없음**(3개 절단 완전 일치), **회계정합**(오차 0), **`zero_hold_frac`=0**(정방향·
   반전 모두), **신호빈도**(23.15/년·4.67/년)가 스펙 예상과 정확히 부합 — 데이터/구현 결함으로
   인한 착시는 아니다.

**완화 요인(정직하게 기록)**:
- 신호 정의·게이트 정의 모두 스펙 예상 빈도와 정확히 일치해, 과거 여러 라운드의 "정의 결함으로
  10~수백배 신호 폭증" 부류의 문제는 이 스펙에 없다.
- 전제의 내적 일관성(베이시스변동성 vs 가격변동성 독립성)이 스펙 설계 단계 우려와 달리 실측으로
  지지됐다 — 아이디어 자체가 무의미하게 설계된 것은 아니다.
- BTC 단일종목·저빈도(연 4~10건) 설계는 스펙이 자인했듯 **구조적으로 이 정도 표본만 가능**하다
  (게이트를 완화해도 §9 `th=60`처럼 표본이 소폭 늘 뿐 PF는 여전히 1 미만). 데이터 기간을 더
  기다린다고 해결될 문제가 아니라(연 4~10건 페이스로는 검증임계 20건에 도달하는 데 추가로
  2~4년이 더 필요), **표본부족이 구조적 한계**임을 강조한다.

**결론**: OOS 표본이 스펙 자신의 사전 임계(15건)에 못 미쳐 통계적으로 확정 판단은 유보한다
(**판단불가**). 다만 사용 가능한 모든 방향성 증거(대조군 열세·부트스트랩 30.2%·셔플 백분위
25~26%·무비용 진단 여전히 <1·파라미터 스윕 불안정)가 일관되게 게이트의 부가가치를 지지하지
않는 쪽을 가리킨다. **라이브에 반영하지 않으며, 재검증하려면 표본을 늘릴 별도 방법(예: 더 낮은
`th_gate`로 빈도 증대 후 재설계, 또는 훨씬 긴 역사 확보)이 필요하다는 점을 기록한다.**
