## 방법 / 재현성

### 데이터
- **1h/15m 선물(um) 캔들**: 직전 라운드들이 이미 받아 캐시해 둔 `scratchpad/klines_cache/
  {SYM}USDT_15m_*.pkl`(2022-01~2026-06, 7종목 전부 54개월 완비)을 그대로 재사용, 1h 는 15m 을
  표준 pandas `resample("1h")` 로 재구성(과거 완결된 15m 봉만 집계하므로 룩어헤드 없음).
- **OI(`sum_open_interest`, 5분 간격)**: 직전 `oi-per-trade-creation-intensity` 라운드가 받아둔
  `scratchpad/oipt_metrics_cache/{SYM}USDT-YYYY-MM-DD.pkl`(2021-11/12~2026-06-30, 7종목 전부)을
  재사용. 1h 버킷의 OI 대표값은 **그 시간대 마지막 5분 스냅샷**(예: 09:00~10:00 버킷 → 09:55 값)
  으로, **수기 검산 2건**(BTC 2023-05-15 09:00 버킷→107875.538, BTC 2024-11-03 17:00 버킷→
  83680.756)에서 raw CSV 값과 **정확히 일치** 확인. 이는 스펙이 지시한 "봉 마감 시점 기준" 정렬과
  일치하고, 1h 봉 자체의 종가 확정 시각(버킷+1h)보다 5분 앞선 값이라 보수적으로 어긋나는 방향(=
  룩어헤드 아님).
- **⚠️ 단위 함정 확인·수정**: `metrics` 의 `create_time` 은 날짜 문자열이라 `format=` 을 명시해
  파싱한 뒤 `.astype("datetime64[ms, UTC]")` 로 klines 의 ms 인덱스와 통일했다(unit 미지정
  파싱 시 us 로 추론되는 함정을 `build_data.py` 단계에서 원천 차단).
- **0-fill 결측 점검**: 7종목 전부 `oi==0` 이 42~118건(전체 39,288~39,408 시간봉의 0.03~0.30%),
  `oi` NaN 이 10건(전 종목 공통, 2024-02-16 14~23시 — 워밍업 아님, 실제 결측). BTC 기준 0-fill
  분포를 확인한 결과 **2024-07-10~15(6일 연속, 28건)** 이 최대 군집으로, 과거 라운드가 반복
  적발한 바로 그 결측 구간과 일치. 전부 `oi==0 | isna()` → NaN → **ffill** 처리(급격한 허위
  ΔOI 스파이크 방지), 오염 트레이드 여부는 아래 §5 에서 별도 확인.

### 파이프라인/타이밍
- **1h 신호**: `elas_window=30봉` 롤링 OLS 로 β = cov(ΔPrice,ΔOI)/var(ΔPrice) 산출(ΔOI 를 ΔPrice 에
  회귀한 기울기와 동치, `pandas.rolling().cov/var()` 폐쇄형), `elas_lookback=1440봉(60일)` 트레일링
  분포 대비 백분위(`rolling().rank(pct=True)`, 자기 자신 포함 트레일링이라 룩어헤드 없음).
- **버스트**: 직전 3개 1h봉 누적 수익률 절대값 ≥ 1.5×ATR14(1h).
- **게이트**: β 백분위 ≤30%+버스트 → **추세추종**(가격 움직인 방향), β 백분위 ≥70%+버스트 →
  **역추세**(반대 방향).
- **15m 확인+체결**: 1h 봉 종료 시각(=신호 확정 시각) 직후 시작하는 **첫 15m 봉**이 최종 방향과
  같은 쪽으로 마감(종가>시가 for 롱)할 때만, **그다음 15m 봉의 시가**로 체결(`shift(1)` 원칙).
  확인 실패 시 그 신호는 폐기(대기 없음).
- **청산**: 추세추종 = SL 고정(entry∓1.0×ATR15) + 트레일링(신고가/신저가−2.0×ATR15, 단조 개선),
  β 백분위가 40~60% 로 복귀하면 조기청산(레짐 소멸). 역추세 = SL 고정(∓0.8×ATR15) + TP 고정
  (±1.0×ATR15) + 최대 6개 15m봉(1.5시간) 시간청산. SL/TP 동시 도달 시 SL 우선(보수적).
  ATR15 는 **확인봉(마지막으로 닫힌 15m봉)** 기준 값을 써서 진입 시각에 미확정 정보 사용 없음.
- **비용/사이징**: 왕복 0.14%(편도 0.07%, 진입·청산 각각 notional 에 부과), 리스크 1%(SL 거리
  기준 수량 산출, `qty=equity*0.01/sl_dist`), 심볼별 독립 $10,000 시작자본, 15m봉 4개(1시간)
  쿨다운.
- **IS/OOS**: IS 2022-01-01~**2024-06-30 23:59:59**, OOS 2024-07-01~**2026-06-30 23:59:59**
  (entry_time 기준). `IS(4360)+OOS(4133)=8493=FULL(8493)` 정확히 일치(경계 사각지대 없음).

## 결과 0 — 스펙 사전요구: 부호 처리(청산 캐스케이드 vs 신규레버리지) 사례검사

스펙은 "가격 급락+OI 급감(청산 캐스케이드)이 β 부호상 '탄력성 낮음'으로 오분류될 위험"을
사전에 경고했다. 7종목 각각에서 `ΔPrice` 하위 1%(급락)+`ΔOI` 하위 1%(급감) 구간과, `ΔPrice`
상위 1%(급등)+`ΔOI` 상위 1%(급증) 구간의 β 백분위를 비교:

| | n(청산성, 급락+OI급감) | β백분위 평균 | n(레버리지성, 급등+OI급증) | β백분위 평균 |
|---|---:|---:|---:|---:|
| 전체 평균(7종목) | — | **73.5** | — | **78.6** |

**결론: 오분류 없음.** 두 시나리오 모두 β 백분위가 **70 이상(고탄력성 구간)** 에 위치해 스펙의
가설대로 "가격과 OI 가 같은 방향으로 함께 움직이면(급락+OI급감, 급등+OI급증 둘 다) 높은 β" 로
일관되게 분류된다. β = cov(ΔPrice,ΔOI)/var(ΔPrice) 의 정의상 부호가 아니라 "함께 움직이는 정도"를
측정하므로 하락 국면에서도 정상 작동한다 — 스펙이 우려한 최악의 혼동 케이스는 실측상 발생하지
않았다(설계 재검토 불필요, 사전 폐기조건 (b) 미해당).

부수 확인: signed_volume-가격방향 일치율(Kyle λ 스펙과 동일 점검, 참고용) 평균 **73.1%**
(90% 미만이라 Kyle λ 자체의 동어반복 우려도 이 데이터에선 기각).

## 자체 발견 버그

- **ms/us 업캐스트(파이프라인 기지 함정, 재발)**: `beta_by_close.index + pd.Timedelta(hours=1)`
  이 `datetime64[ms, UTC]` 인덱스를 pandas 3.0.5 에서 조용히 `datetime64[us, UTC]` 로 업캐스트해
  `merge_asof` 가 `MergeError`(incompatible merge keys)로 즉시 실패했다(직전 여러 라운드가 발견한
  동일 패턴의 재발). `strat.py`·`sweep.py` 양쪽에서 `.astype("datetime64[ns, UTC]") +
  Timedelta → .astype("datetime64[ms, UTC]")` 로 명시 통일해 수정. 이번엔 조용히 신호가 줄어드는
  형태가 아니라 **즉시 예외로 죽어서 바로 발각**됐다(은폐 위험이 낮은 형태의 재발).
- 그 외 치명적 구현 버그는 발견되지 않음(회계정합·룩어헤드·조인·반전대칭성 전부 정상 확인).
