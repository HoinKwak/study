## 0. pandas 함정 점검(과제 지시 사항)

- **UM·CM 병합 dtype**: `calc_time`(ms epoch int) → `pd.to_datetime(unit="ms")` 후 명시적으로
  `.astype("datetime64[ns]")` 통일(`Timedelta` 덧셈을 쓰지 않고 `.dt.floor("h")`만 사용 —
  과거 여러 라운드가 경고한 "`datetime64[ms]`+`Timedelta` 덧셈의 조용한 us 업캐스트" 함정
  자체가 발생하지 않는 경로). 병합 후 BTC/XRP 두 종목에서 `dtype=datetime64[ns]`,
  `div_z` NaN율 1.38~1.43%(윈도 워밍업분, 정상) 확인.
  `bool.shift(1).fillna(False)` object-dtype 함정도 이 코드는 절대 임계값 비교(`>=`,`<=`)만
  사용하고 shift 기반 불리언을 쓰지 않아 해당 없음.
- **klines(um) 로더**: 기존 `bt_common.load_klines`(검증된 공용 모듈) 그대로 재사용 — `ns` 명시
  변환 로직 이미 내장.

실제 신호가 발생하는 구간(UM+CM 둘 다 존재 = 2022-07-22~2026-06-30, 3.94년)을 분모로 계산:

**`div`(채택안)의 실측 빈도(23.1~38.1건/년)는 스펙 예상(40~90건/년)의 하한 근방~하한 이하**로
과거 여러 라운드의 10배~수백배급 정의결함과는 전혀 다른, **경미한(1.1~3.9배 이내) 편차**다.
신호 정의(윈도·임계값·부호확인 게이트) 자체는 대체로 합리적으로 설계됐다고 판단한다.

## 4. 핵심 대조군① — 정보원 무력화(COIN-M 블록셔플 20회)

COIN-M 펀딩 시계열을 연속 10정산(=200/3일) 블록 단위로 무작위 재배열한 뒤 `div_z`를
재계산해 20회 반복 실행(seed 0~19):

```
기본(채택, 실제 COIN-M) FULL: n=998 PF_gross=0.9335 PF_net=0.8551
셔플 20회 PF_gross 범위: 0.896~1.131 (평균≈0.999)
셔플 20회 PF_net   범위: 0.829~1.045 (평균≈0.924)
기본안 PF_gross 백분위(셔플 분포 내): 15.0%  - 20개 중 17개가 기본안보다 우수
기본안 PF_net   백분위: 15.0%
셔플 평균 진입건수: 919.0 vs 기본 998(발화율 -7.9%, 게이트가 정보와 무관하게 발화율만
                    고정하는 함정은 아님 - 실제 데이터가 셔플보다 소폭 더 자주 발화)
```

**이번 라운드의 결정적 발견**: 실제 COIN-M 데이터를 쓴 기본안이 **20개 무작위 셔플 대조군
중 17개(85%)보다 성과가 낮다** — "COIN-M 순서 정보가 무가치하다"는 스펙의 폐기기준②(§정규화
게이트 논증)을 훨씬 넘어서, **실제 정보를 쓰는 것이 무작위 노이즈보다 구조적으로 더 나쁘다**는
뜻이다. 과거 라운드 중 "정보원 무력화 대조군이 원본을 이긴 사례"(Weis Wave 건)와 같은 패턴이
이번에도 재현됐다. 발화율 자체는 셔플과 크게 다르지 않아(-7.9%) "게이트가 정보와 무관하게
발화율만 고정"하는 종류의 함정(직전 스펙 요건에서 명시된 `corr_pctile` 사례)은 아니다 —
문제는 발화 빈도가 아니라 **발화된 시점에서 진짜 COIN-M 데이터가 셔플된 COIN-M 데이터보다
방향 판단에 더 나쁜 신호를 준다는 것**이다.

6. **방향반전 대조군이 정방향보다 우수**: OOS PF_net 1.160(반전) vs 0.759(정방향), R-배수
   재계산에서도 정방향만 유의하게 음(t=-2.48)이고 반전은 양(t=+1.15, 비유의) — "국지적 과열을
   페이드한다"는 스펙의 방향성 가설이 데이터에서 지지되지 않는다.

**완화 요인(FAIL이지만 정직하게 기록)**:
- 신호빈도는 스펙 예상(40~90건/년)의 하한 근방(실측 23~38건/년, 최대 3.9배 이내 편차)으로,
  과거 여러 라운드의 10~500배급 정의결함과는 성격이 다르다 — 신호 정의 자체는 대체로
  합리적으로 설계됐다.
- 동어반복 우려(스펙 §동어반복 점검)는 실측 기각됐다 — `div_z`와 `z_funding_only`의
  트리거시점 상관이 0.29~0.68로 0.8 미만이라, "COIN-M 정보가 USDT-M 레벨 재탕"은 아니다
  (오히려 §4가 보여주듯 "다른 정보이지만 해로운 정보"라는, 더 안 좋은 결과).
