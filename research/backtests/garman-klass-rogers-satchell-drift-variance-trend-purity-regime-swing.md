- **GK/RS/purity 정의**(스펙 원문 그대로):
  ```python
  def compute_gk_rs(df):
      o, h, l, c = df["open"].clip(lower=1e-12), df["high"].clip(lower=1e-12), \
                   df["low"].clip(lower=1e-12), df["close"].clip(lower=1e-12)
      ln_hl = np.log(h / l); ln_co = np.log(c / o)
      gk = 0.5 * ln_hl ** 2 - (2 * np.log(2) - 1) * ln_co ** 2
      ln_hc = np.log(h / c); ln_ho = np.log(h / o); ln_lc = np.log(l / c); ln_lo = np.log(l / o)
      rs = ln_hc * ln_ho + ln_lc * ln_lo
      return gk, rs
  # purity_N(t) = rolling_mean(gk, 14) - rolling_mean(rs, 14)
  ```
  4h~5분 저유동 알트 예외(H=L, O=C): H=L봉은 7종목 전부 0건(실측), O=C봉은 알트에서 최대 90건
  (ADA)까지 존재하나 `ln(C/O)=0` 이 되어 정상 계산(GK/RS 비유한값 0건, 전 종목 실측 확인).
- **롤링 인과 백분위(룩어헤드 방지 핵심)**: `purity_pctile(t)` 는 `[t-99, t]`(자기 자신 포함,
  regime_lookback=100봉) 구간 값들 중 `purity(t)` 가 차지하는 백분위(0~100). 오직 그 시점까지
  이미 확정된 봉만 참조 — 코드:
  ```python
  def rolling_pctile_causal(series, lookback):
      arr = series.to_numpy(float); out = np.full(len(arr), np.nan)
      for t in range(len(arr)):
          window = arr[max(0, t-lookback+1):t+1]
          window = window[~np.isnan(window)]
          if len(window) < lookback or np.isnan(arr[t]):
              continue
          out[t] = (window <= arr[t]).mean() * 100.0
      return pd.Series(out, index=series.index)
  ```
  **룩어헤드 검증**: BTC 5,000봉·ETH 3,000봉·ADA 7,000봉·XRP 2,000봉 4개 종목에서 절단 재실행 —

  절단 이전 신호(EMA크로스+게이트) 리스트도 완전 일치(BTC 44건=44건). 구조적으로 미확정 봉 참조

지표와 확실히 다른 정보를 담고 있다(동어반복 아님).

**⚠️ 추가 발견(요청 범위 밖이나 판정에 중요한 함의)**: `purity_N`(=GK-RS) 의 **표본평균이 7종목
전부 음수**다(BTC -5.8e-6 ~ DOGE -6.4e-5). GK 공식의 `-(2ln2-1)ln(C/O)^2` 항은 **드리프트가 클수록
GK 값을 오히려 깎는 방향**(계수가 음(-)으로 곱해짐)이라, 봉 내부 방향성 움직임(`|ln(C/O)|`)이
레인지(`|ln(H/L)|`)의 평균 **44.3~46.4%**(7종목 실측, 스펙이 우려한 "24/7 이라 갭이 작아 무시할
수준"이라는 전제와 달리 결코 작지 않음)에 달할 만큼 크다 보니 GK 평균이 RS 평균보다 구조적으로
낮게 나온다(7종목 전부 `mean(GK)<mean(RS)`, 예: BTC GK=1.462e-4 vs RS=1.520e-4). 이는 GK 원 공식
자체가 학술 문헌에서 종종 지적되는 "강한 방향성(트렌드) 구간에서 오히려 과소추정"하는 성질과
부합하며(교정항 부호가 반대 효과를 낸다), **spec 이 가정한 "GK≫RS 일 때 드리프트 강함" 방향이
공식 구조상 보장되지 않을 수 있음**을 시사한다. 다만 이 발견은 순위(percentile) 기반 게이트
자체를 무효화하지는 않으므로(백분위 게이트는 상대적 순서만 쓰므로 부호 반전과 무관하게 작동)
백테스트는 스펙 원문 정의 그대로 계속 진행했다.
