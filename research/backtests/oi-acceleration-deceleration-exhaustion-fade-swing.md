## 결론 먼저: **FAIL (사전 등록 폐기조건 (b)·(c)·(e) 동시 해당)**

스펙이 "착수 즉시 최우선으로 돌리라"고 명시한 동어반복 점검에서, `oi_accel`(2차미분) 기반
`accel_z`가 기존 스펙 `multi-timeframe-oi-slope-divergence-regime-swing.md`의 `z_short`
(4h 6봉 OLS 기울기, 90봉 z-score)를 1봉 차분한 값과 **상관 0.87(풀링), 종목별 0.858~0.880**로
스펙 자신이 사전 등록한 폐기조건 (b)(≥0.8)에 해당한다. 여기에 더해 셔플 대조군(조건 (c))도
뚜렷이 이기지 못했고(백분위 29%), 대조군②(가격필터 제거판) 대비 부가가치도 없었다(조건 (e)).
표본은 충분(OOS n=191)하고 룩어헤드·회계정합·데미닝 등 구현결함도 없어 **판단불가가 아니라
확정적 FAIL**로 판정한다.

## 1. 데이터·재현성

- **유니버스**: BTC/ETH/BNB/SOL/XRP/DOGE/ADA (표준 7종목).
- **데이터**: `data.binance.vision` 선물(um) 4h klines(월별 zip, raw 컬럼 보존) + `metrics`
  일별 zip(5분 간격 `sum_open_interest`). 1d 확인 TF는 스펙상 "참고용, 필수 게이트 아님"이라
  본 백테스트에서는 사용하지 않았다(진입 로직에 미포함).
- **캐시 재사용**: 같은 7종목·같은 기간(2021-11-20~2026-06-30)의 klines_cache·
  oipt_metrics_cache(직전 `oi-per-trade-creation-intensity-regime-swing` 라운드에서 이미 실물
  검증된 캐시)를 그대로 재사용했다. 종목당 metrics 일별 zip 1,673~1,684건, 4h klines 59개월분
  전량 확보 확인(재다운로드 불필요).
- **ns/ms 함정 점검**: `create_time`(날짜 문자열)은 `pd.to_datetime(..., utc=True)` 후
  `datetime64[ns]`로 명시 캐스트, klines의 정수 epoch는 `unit="ms"` 명시 후 동일하게 ns로
  캐스트해 병합 — 두 인덱스 단위 불일치 없음.
- **0-fill 결측 처리**: 4h 버킷에 5분 원본 관측치가 하나도 없는 경우(`oi_n==0`) 또는
  `oi_last<=0`인 경우 `oi_last`를 NaN 처리해 `oi_roc`/`oi_accel`/`accel_z` 계산에서 자동
  제외(허수 -100%/+inf 스파이크 차단). 실측 결측 버킷: 종목당 2~66개(전체 ~10,100개 4h 버킷
  중 최대 0.65%, BTC는 2개로 가장 양호) — 과거 라운드에서 확인된 "`sum_open_interest`는 글로벌
  필드라 안정적"이 이 스펙에서도 재확인됨.
- **기간**: IS 2022-01-01~2024-06-30 23:59:59 / OOS 2024-07-01~2026-06-30 23:59:59 (IS_END를
  23:59:59로 명시해 6/30 장중 진입 누락 없음).
- **회계 정합**: `n=432, max|raw_pnl - fees - pnl| = 0.0000000000`.
- **표본 분할 검산**: `len(IS)+len(OOS) = 241+191 = 432 = len(FULL)`. ✅
- **수수료/슬리피지**: 편도 수수료 0.05% + 편도 슬리피지 0.02% = 편도 0.07%, 왕복 0.14%

- **리스크 사이징**: 트레이드당 계좌자본 1% 리스크(`RiskManager.build_plan_with_stop`),

## 2. ⚠️ 최우선 점검: 동어반복(tautology)

### 2-1. `accel_z(t)` vs `z_short(t)-z_short(t-1)` 상관 — **폐기조건 (b) 트리거**

`z_short`는 `multi-timeframe-oi-slope-divergence-regime-swing.md`의 정의 그대로 재현
(4h OI 6봉 OLS 기울기 → 구간평균 OI로 정규화 → 90봉 z-score). `pandas.corr()`(pairwise)로 계산.

| 종목 | n_valid | corr |
|---|---|---|
| BTCUSDT | 9,501 | 0.8800 |
| ETHUSDT | 9,556 | 0.8717 |
| BNBUSDT | 9,460 | 0.8664 |
| SOLUSDT | 9,526 | 0.8768 |
| XRPUSDT | 9,430 | 0.8603 |
| DOGEUSDT | 9,460 | 0.8580 |
| ADAUSDT | 9,460 | 0.8718 |
| **POOLED** | **66,393** | **0.8688** |

7종목 전부 개별적으로도 0.858 이상, 풀링 0.8688 — 스펙 자신이 사전 등록한 폐기조건 (b)
("상관 0.8 이상이면 동어반복으로 폐기, 해당 정보는 `multi-timeframe-oi-slope-divergence-
regime-swing.md` 결과로 대체")에 정확히 해당한다. 과거 3건(0.91~0.99, 93~99%)보다는 낮지만
스펙이 스스로 그은 문턱(0.8)을 전 종목이 예외 없이 넘었으므로 사후에 기준을 완화하지 않고
그대로 적용한다.

이는 이론적으로도 납득 가능하다 — `oi_accel`은 "3봉 평균 OI% 변화율의 3봉 전 대비 변화"로
사실상 OI 레벨의 약 6봉(24h) 구간에 대한 국소 곡률을 측정하는데, `z_short`의 6봉 OLS 기울기의
1봉 차분 역시 같은 6봉 창을 한 칸씩 밀어가며 측정하는 국소 곡률 근사이므로, 서로 다른 평활화
방식(이동평균 차분 vs 회귀기울기 차분)일 뿐 **본질적으로 같은 정보(2차미분)를 다른 방식으로
추정**한 것에 가깝다.
