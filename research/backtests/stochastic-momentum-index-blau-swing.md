## 방법 / 재현성

### 왜 `SleeveBacktester` 를 안 썼는가
4h 추세필터(EMA50 기울기 · EMA200 상회)가 `SleeveBacktester` 의 재계산 창(SIGNAL_WINDOW=200,
CONFIRM_WINDOW=100)에서 워밍업 오염 위험이 있고(EMA200 이슈, `chandelier_exit_swing.py` 와
동일 전례), "oversold/overbought 확인형 크로스오버 + 반대크로스 청산 + 시간청산" 상태기계도
기존 슬리브 인터페이스(Scalp/Mid/Swing)와 맞지 않는다. 전례를 따라 커스텀 리플레이 엔진을
작성했다. 지표는 전체 히스토리에 대해 한 번에(EMA/ATR/rolling 모두 인과적 함수, 미래 누출
없음) 계산하고, 각 시점 i 에서 i 이하 데이터만 사용해 결정한다.

### SMI(Blau) 계산 — 신규 구현(스펙 원문 그대로)
```
range_mid = (highest_high(k_len) + lowest_low(k_len)) / 2
rel_diff  = close - range_mid
rel_range = highest_high(k_len) - lowest_low(k_len)
smoothed_x = EMA(EMA(x, d_len), d_len)     # 이중 EMA 평활
SMI = 100 * smoothed(rel_diff) / (0.5 * smoothed(rel_range))
signal_line = EMA(SMI, d_len)
```
값 범위·분포 확인(BTCUSDT 1h, 4.4년): 평균 +2.9, 표준편차 42.0, 범위 [-92.9, +93.5] — SMI 정의상
±100 부근에 유계이며 정상 범위. 계산 버그 없음을 확인.

### 멀티 TF 정합(룩어헤드 방지)
1h 신호봉 시각 t 에서 "t 까지 **완결된** 마지막 4h 봉"만 추세필터에 사용한다
(`elder_ray_bull_bear_power_swing.py::daily_avail_index` 와 동일한 `searchsorted` 원리를
4h 단위로 일반화 — 상위봉 종료시각 대비 신호봉 시각 비교, 미완결 상위봉 배제).

### 진입 (스펙 "역추세 확인형" — 주 판정 대상)
- 롱: SMI 가 최근 `os_lookback=6`봉 내 oversold(-40) 아래로 내려간 적 있고, 이번 봉에
  시그널선을 상향 돌파(`SMI[t-1]≤sig[t-1]`, `SMI[t]>sig[t]`) **AND** 4h 추세필터
  (`EMA50(4h)` 기울기>0 **OR** 종가>`EMA200(4h)`).
- 숏: 대칭(overbought(+40), 하향돌파, 4h 하락추세필터).
- (스펙의 "대안: 추세추종형" — 레인지 필터 없이 크로스오버만 — 은 `require_range_filter=False`
  로 A/B 참고 실행, 아래 파라미터 민감도 표에 포함. **결론에 영향 없음**, 오히려 더 나쁨.)

### 청산 (정성 규칙의 ATR 정규화, 설계 판단 명시)
- 반대 크로스오버 발생 시 청산(종가). 스펙의 "청산 후 반전 진입"은 **채택하지 않음**(청산만
  수행 — 반전진입까지 포함하면 상시 시장참여 상태가 돼 리스크 프로필이 왜곡됨, 설계 판단).
  "반대편 극단(±40) 도달 시 부분청산"도 트레이드 단위 PF 계산을 복잡하게 만들어 채택하지
  않음(전량 반대크로스오버 청산으로 단순화).
- SL = `entry ∓ min(|entry-스윙저가/고가(10봉)|, 2.0×ATR(14,1h))` 중 **더 타이트한 쪽**
  (elder-ray 검증과 동일한 "또는" → tighter-of-two 정규화 방식, 일관성 유지).
- 시간청산: `max_hold=40`봉(1h) 초과 시 종가 강제 청산.
- 봉 내 우선순위: SL 인트라바 → 반대크로스오버(종가) → 시간청산(종가).
- 쿨다운: 청산 직후 3봉 재진입 금지(휩쏘 방지, `SleeveBacktester` 관례를 1h TF 스케일로 조정).

- **1차 출처(FMZQuant)에 성과 수치가 없어 "재현 실패"가 아니라 최초의 독립 검증**이다.
  그 결과는 명확한 FAIL: 풀링 IS PF 0.87(t=-3.03), 풀링 OOS PF 0.76(t=-5.79) — **IS·OOS
  둘 다 순손실이며 OOS 가 더 나쁘다**(전형적인 "표본외 악화" 패턴).
- **표본은 충분하다**(IS 5000건, OOS 4357건, 종목당 600~765건씩) — HOLD(판단보류) 사유 없음.
  결정적 결론이 가능한 규모다.
- **7종목×2구간=14개 조합 중 13개가 PF<1**, 유일한 예외(SOL IS, PF1.02)도 통계적으로
  무의미(t=0.21)하고 같은 종목의 OOS 에서 다시 실패(0.79) — 종목 간·구간 간 일관된 실패.
- **XRP 를 빼도 결과가 거의 그대로**(§5.4 leave-one-out) — 특정 단일종목 착시가 아니다.
- **파라미터 민감도**(k_len·d_len·ob/os·쿨다운·시간청산 전부 스펙 범위 내에서 스윕)에서
  모든 변형이 PF 0.70~0.81 로 실패권에 머문다. 대안으로 제시된 "추세추종형 순수 크로스오버"
  변형도 더 나쁘다(오히려 참고용 A/B 비교가 통과 가능성을 뒷받침하지 못함).
- 거래빈도가 스펙의 "스윙"(원문 대상 BTC 1h 신호) 기대보다 훨씬 높아(평균 보유 6.5시간)
  수수료 드래그가 크다(자본의 65~116%) — 이는 SMI 자체가 1h 노이즈에 자주 반응하는
  오실레이터 특성상 구조적인 문제로 판단된다.

**결론: 명시된 파라미터·범위 어디에서도 우리 프레임워크(수수료+슬리피지 반영)에서 통과
