# 1) 1h 신호봉에 대응하는 12개 5분 OI 관측치(oi_1..oi_12): 정확 라벨 reindex(그리드가

offsets = [0,5,...,55]분
oi_mat[i, k] = oi5.reindex([signal_open_time_i + offsets[k]])  # 없으면 NaN

# 2) Donchian(20, 1h, 신호봉 제외): donch_up[i] = max(high[i-20:i]), donch_lo[i] = min(low[i-20:i])
# 3) 단조성 위반: up_viol = count(oi[k] < oi[k-1]*(1-0.05%)), down_viol 대칭
# 4) 롱: close[i] > donch_up[i] AND up_viol<=2 AND oi_12>oi_1 AND ~missing_any
#    숏: close[i] < donch_lo[i] AND down_viol<=2 AND oi_12<oi_1 AND ~missing_any
# 5) 체결: 신호봉 종료시각(=다음시 정각) 15m봉 시가 + 슬리피지(shift(1) 컨벤션)
# 6) SL 거리(방향 무관, 대칭): dist = |entry_ref - 신호봉시가| * stop_mult(1.0)
#    (라이브 ScalpStrategy._entry 의 `stop = entry - stop_mult*(entry-open)` 을 15m/1h
#     경계를 넘어 그대로 적용 — entry_ref/신호봉시가 모두 방향에 무관한 raw 값이라
#     반전 대조군에서도 항상 대칭 재배치가 자동 성립하는 구조, 과거 라운드들에서 반복된
#     "반전 시 SL 거리 비대칭 퇴화" 버그 클래스가 이 정의에서는 애초에 발생 불가)
# 7) 트레일링: 최고가/최저가 갱신마다 stop = max(stop, run_ext - ATR(14,1h)*2.0)(롱, 숏 대칭)
#    ATR 은 신호봉 시점 값으로 트레이드 내내 고정(설계 선택, 아래 "해석" 절 참조)

## 해석·설계 선택(스펙 모호성 명시)

- **SL 정의**: 스펙 문구 "손절: 신호봉 시가(진입가 대비 대칭 배치, `stop_mult`=1.0×ATR(14,1h))"
  는 표현이 이중적이다(리터럴 "신호봉 시가" vs "ATR 배수" 두 가지 다른 정의로 읽힐 수 있음).
  라이브 `ScalpStrategy._entry`(`src/crypto_trader/strategy/scalp.py:191`)의 실제 코드
  `stop = entry - stop_mult*(entry-open)` 를 그대로 적용해 이중성을 해소했다 — `stop_mult`=1.0
  일 때 정확히 "신호봉 시가"가 되고, 파라미터 스윕 범위(0.8~1.5)도 이 배수 해석과만 정합적이다
  (신호봉 시가 자체를 1.5배 하는 것은 무의미하므로 배수 해석이 스펙 파라미터 절과도 일치).
  1h 신호봉과 15m 진입의 TF 경계를 넘어 적용했다는 점만 스펙에 명시적이지 않은 설계 판단이다.
- **ATR 트레일링 갱신**: "ATR(14,1h)×2.0 트레일링"이 트레이드 내내 ATR 을 재계산하는지 신호
  시점에 고정하는지 불명확 — SL 정의(신호봉 시가 기준)와의 일관성을 위해 **신호 시점 ATR 값을
  트레이드 전체에서 고정**하는 쪽으로 구현했다(라이브 `momentum_trail` 모드와 동일 패턴,
  `sleeve_backtester.py`의 `ref["atr"] = atr_v`로 1회 저장 후 재사용하는 방식과 정합).
- **동시보유**: 스펙에 명시 없음. 프레임워크 관례(라이브·`SleeveBacktester` 전부 심볼당 단일
  포지션)를 따라 동시보유 금지로 구현 — 아래 "자체 발견 버그" 절 참조.
