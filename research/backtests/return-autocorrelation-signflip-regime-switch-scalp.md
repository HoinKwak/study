## 1) 재포장 점검 (⭐최우선 검증)

`rho(t)` = 1h 로그수익률의 롤링 60봉 lag-1 Pearson 자기상관. 비교지표는 전부 순수 pandas/numpy로
구현(`indicators.py`): Hurst(R/S, 60봉을 10/12/15/20/30/60 등분해 log(R/S) vs log(m) 회귀 기울기),
VR(2)(Lo-MacKinlay 2기간 중첩 분산비율), ROC(60봉), 실현변동성(60봉 std), ADX(14, 기존
`crypto_trader.signals.indicators.adx`).

### 전 구간 상관 (pooled n=275,189)

| 비교지표 | r |
|---|---|
| Hurst | +0.3194 |
| **VR(2)** | **+0.9586** |
| ROC(60) | +0.0196 |
| 실현변동성(60) | +0.0780 |
| ADX(14) | +0.0896 |

종목별 `rho~VR2`: BTC 0.9536 · ETH 0.9483 · BNB 0.9664 · SOL 0.9671 · XRP 0.9554 · DOGE 0.9591 ·
ADA 0.9618 (전부 `|r|>=0.8` 압도, `rho~Hurst`는 0.2668~0.3425로 전부 미달).

### 트리거 시점 상관 (gated 베이스 실제 진입 신호봉만, n=25,722)

| 비교지표 | r |
|---|---|
| Hurst | +0.3676 |
| **VR(2)** | **+0.9675** |
| ROC(60) | +0.0260 |
| 실현변동성(60) | +0.0845 |
| ADX(14) | +0.1113 |

종목별 `rho~VR2`(트리거 시점, n=3,273~4,204/종목): BTC 0.9710 · ETH 0.9610 · BNB 0.9723 ·
SOL 0.9793 · XRP 0.9519 · DOGE 0.9682 · ADA 0.9669 — **7종목 전부 0.95 이상**.

서브모드별(트리거 시점): MR `rho~VR2`=+0.8345(n=21,925), MOM `rho~VR2`=+0.7153(n=3,797). MOM
서브모드만 놓고 보면 0.8 문턱을 근소하게 밑돌지만(표본이 작고 MOM 레짐 자체가 `rho>=+0.15`로
편중된 부분표본이라 상관이 다소 눌린 것으로 보임), 스펙 (c)가 요구하는 "전구간·트리거시점 모두"
기준은 **풀링·종목별 양쪽에서 이미 충족**된다.

**결론**: `rho`와 ROC·실현변동성·ADX 사이엔 재포장 문제가 없다(독립 정보).
Hurst 재포장 우려(스펙 우려 ①)도 기각된다(상관 0.27~0.37).

⚠️**정정(리뷰어 반박, 2026-09-02) — VR 재포장 '확증'은 사실이 아니다.**
본문은 `rho`(1h·60봉)와 `VR(2)`를 **같은 1h·60봉 시계열로** 계산해 상관 0.96을 얻고, 이를
근거로 경쟁 스펙 `variance-ratio-overshoot-fade-scalp.md`의 재구현이라고 일반화했다.
그러나 **그 스펙은 VR(4)를 5분봉·96봉(8시간) 창으로** 쓴다(`vr_window=96, vr_q=4, 5m`).
본문은 그 실제 파라미터를 한 번도 테스트하지 않았다. 리뷰어가 5m 덤프를 새로 받아 계산한 결과:

| 비교 | r |
|---|---:|
| rho(1h,60) vs VR(2)(1h,60) — 본문이 실제 쓴 것 | +0.9586 (재현됨) |
| rho(1h,60) vs VR(**4**)(1h,60) — q만 스펙값으로 | BTC +0.7390 / ETH +0.7332 (**0.8 미달**) |
| rho(1h,60) vs **VR(4)(5m, 96봉=8h)** — 경쟁 스펙의 실제 파라미터 | BTC **+0.0126** / ETH **+0.0026** |

**즉 실제 경쟁 스펙의 통계량과는 사실상 무상관이다**(n=472,152, 두 종목 모두). q를 2→4로만
바꿔도 문턱을 못 넘고, 시간축까지 스펙대로 바꾸면 상관이 소멸한다. 본문이 얻은 0.96은
`VR(2) ≈ 1+ρ(1)`이라는 **근-항등식을 같은 시계열로 짜맞춘 결과**여서 거의 동어반복이었다.

→ **폐기조건 (c) 판정을 '충족'에서 '미충족'으로 정정한다.** 이 건은 재포장이 아니라
**'독립 정보인데 가치가 없었던' 사례**다(GK/RS·이중VWAP·웍 브레드스에 이어 네 번째).
**FAIL 결론은 폐기조건 (b) 성과 근거만으로 이미 확정적이므로 판정은 바뀌지 않는다.**

## 7) 발견한 버그(구축 단계에서 즉시 수정, 산출물 오염 없음)

1. `engine.py`의 Donchian 브레이크아웃 계산에서 `close > high_prev_max`가 이미 numpy 배열끼리의
   비교라 결과가 numpy bool 배열인데 `.to_numpy(bool)`을 재호출해 `AttributeError`로 즉시
   크래시. **최초 실행이 크래시로 종료돼 어떤 수치도 산출되지 않은 상태에서 수정**했으므로 "수정
   전/후 수치 비교"는 해당 없음(수정 전에는 결과 자체가 없었음).
2. `run_diagnostics.py`의 비중첩 표본 마스크 계산에서 파이썬 `~(bool)`(비트단위 NOT)을 논리부정
   대신 사용해 `True→-2, False→-1`이 되는 버그로 `KeyError` 크래시. `not (...)`로 수정. 이 역시
   크래시 직후 수정이라 수치 오염 없음.
3. 반전 대조군의 MR EMA복귀 TP 퇴화(§5)는 버그가 아니라 **진입선택 편향에 따른 구조적 퇴화**이며,
   CLAUDE.md 규칙에 따라 제3의 대안(TP 비활성판)을 별도 실행해 병기했다(원판 결과도 폐기하지 않고
   함께 기재).
