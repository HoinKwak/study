# BTC 웍(wick) 리젝션 알트 브레드스 페이드 — 재현 스크립트

```
python3 download.py   # data.binance.vision 15m klines 7종목 2022-01~2026-06 (parquet 캐시)
python3 analyze.py    # 전체 파이프라인 실행, out_summary.json / out_base_trades.csv 산출
```

- `common.py` — 데이터 로딩, ATR/웍 지표 계산(`crypto_trader.signals.indicators.atr` 재사용), PF(R)/t-stat.
- `engine.py` — 신호(BTC 웍 리젝션 + 알트 6종목 브레드스 확인) 탐지 + 체결(스윙10봉/RR목표 TP,
  웍극값+buffer SL, 8봉 시간청산) 시뮬레이션. 반전 대조군은 리스크거리를 원신호 기준 1회 계산해
  대칭 재배치(청산조건도 `trade_direction` 기준으로 완전히 방향 분기).
- `analyze.py` — IS/OOS/FULL net·gross 집계, 캘린더일 de-clustering, 5일 롤링 클러스터 손실
  대칭점검, 반전 대조군, 대조군①(게이트 제거)/②(변동성 z-score 대체 게이트, 표본수 매칭)/LOO(알트별
  제외), 파라미터 스윕 17변형, 재포장 상관(전구간+트리거시점), 룩어헤드 절단감사, 무작위 방향배정
  플라시보(200회) + 승률고정 순열검정(200회), 사전 폐기조건 자동판정.

산출: `out_summary.json`(전체 수치), `out_base_trades.csv`(기본판 개별 트레이드).

## 주요 설계 선택(문서화)
- **인덱스 정렬**: BTC 인덱스 ∩ 6개 알트 인덱스(교집합)만 신호 대상. 15m은 전 종목 동일 UTC 경계
  마감이라 별도 리샘플 불필요.
- **confirm_n 산출**: 신호봉(t) 자신의 종가 기준 웍 조건(그 봉이 이미 닫혔으므로 룩어헤드 아님),
  진입은 t+1봉 시가.
- **리스크 거리**: 원신호(raw_direction, 웍이 자연스럽게 만드는 페이드 방향) 기준으로 SL 거리를
  1회 계산 후, 반전 대조군에서는 이 크기를 그대로 반대편에 대칭 재배치(`risk_distance` 재사용).
  스톱을 반전 방향의 "자연스러운 극값"으로 재계산하지 않음(직전 라운드 신규 규칙 준수).
- **TP(스윙/RR)**: 실제 체결 방향(`trade_direction`) 기준으로 재계산(익절은 서사적 무효화가 아닌
  일반 이익실현 메커니즘이라 방향 재계산이 구조적 편향을 만들지 않음 — SL과 달리 신호봉 자신의
  국소 극값에 의존하지 않는 별도 10봉 윈도우 사용).
- **대조군③(무작위 알트 서브셋)**: 스펙 문구는 "6종목 중 무작위 조합"이지만 표준 유니버스가 알트
  6종목으로 고정돼 있어 더 큰 유니버스에서 "다른 알트 조합"을 뽑을 여지가 없음. 대신 **LOO(알트별
  제외, 5종목으로 confirm_n 재계산)**로 특정 알트 의존도를 검증(본문 참고).
