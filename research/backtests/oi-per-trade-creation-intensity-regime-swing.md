  간격 `sum_open_interest`). 4h 블록 집계는 스펙 정의대로 `oi_last(블록 마지막 5분값) −
  oi_first(블록 첫 5분값)`. 데이터는 2021-11-20~2026-06-30, 총 11,788건 일별 metrics 요청 중
  11,722건 성공(404 66건, 0.56%) — 종목당 평균 결측 4h 블록 68개(0.67%), BTC만 2개로 가장 양호.

- **재현성 주의**: 이번 라운드는 컨테이너 재시작으로 중단된 이전 세션이 스크래치 디렉토리에
  남겨둔 원시 데이터 캐시(`oipt_data_cache.pkl`, `oipt_metrics_cache/`)를 재사용했다. 캐시가
  이 스펙 전용으로(스펙의 `oi_last-oi_first` 정의와 정확히 일치하는 컬럼 구조로) 만들어져 있어
  재사용했으나, **신뢰도 확인을 위해 `oipt_fetch_data.py --verify-only`로 2024-03-15 BTC의
  `oi_last`·`count` 6개 4h 블록을 원본 재다운로드와 대조해 완전 일치를 확인**했다. 스크래치
  캐시는 세션 종료 시 소멸할 수 있어(구조적 취약점, 과거에도 반복 지적됨) 재실행 시
  `oipt_fetch_data.py`(캐시 없으면 새로 받는 로직 포함)로 처음부터 재생성 가능하다.
- **ms/us 함정 점검**: `create_time`은 날짜 문자열이라 `pd.to_datetime(unit=...)` 미지정으로
  파싱(문자열에 `unit=` 지정 시 즉시 에러가 나므로 이 경로 자체가 구조적으로 안전). klines의
  정수 epoch는 자릿수로 ms/us 자동판별 후 명시 파싱. 두 인덱스 모두 최종 `datetime64[ns]`로
  통일해 병합, 실측 확인.
- **기간**: IS 2022-01-01~2024-06-30 23:59:59 / OOS 2024-07-01 00:00:00~2026-06-30 23:59:59.
  진입 시각(체결 시각, `open[t+1]`) 기준으로 IS/OOS 배정. **IS n=1,756 + OOS n=1,433 = 3,189 =
  FULL n=3,189 — 정확히 일치**(경계 사각지대 없음).
- **비용**: 왕복 0.14%(편도 테이커 0.05% + 슬리피지 0.02%), 진입 체결 `open[t+1]×(1±슬리피지)`.
  손절/익절은 인트라바(고저 터치) 실시간 체결, 레짐 청산/시간 청산은 신호 확정봉 다음봉 시가
  체결(진입과 동일한 `shift(1)` 원칙).
- **사이징**: `risk_amount = equity×1%`, 레버리지 30x 클램프 시 노셔널 상한으로 수량 축소(리스크
  금액도 동일 비율 축소되는 효과).
- **회계정합**: `max|raw_pnl_accum − fees − pnl| = 0.0000000000` (완전 일치).
- **룩어헤드 감사**: BTC 데이터를 마지막 500봉(약 83일) 절단 후 재실행 → 절단 시점 이전
  안전마진(35봉) 이전 거래 421건이 전체 실행분과 **방향·시각·체결가·손익·청산사유까지 완전
  일치**. 1d EMA50은 스펙 요구대로 "완결된 상위봉"만 쓰도록 1일 지연시켜 4h 봉에 asof 매핑 —
  2024-03-15 하루 6개 4h 봉 전부 전날(D-1) 종가 기준 EMA만 참조함을 직접 확인(당일 봉이 당일
  EMA를 절대 참조하지 않음).

## 1단계: ATS 상관 + 전제 방향 실측 검증 (최우선)

**① `oi_pt` z-score vs 평균체결규모(ATS=quote_volume/count) z-score 상관계수**(90봉 롤링, 종목별):

| 종목 | 상관계수 |
|---|---|
| BTCUSDT | +0.046 |
| ETHUSDT | +0.052 |
| BNBUSDT | +0.184 |
| SOLUSDT | +0.064 |
| XRPUSDT | +0.095 |
| DOGEUSDT | +0.113 |
| ADAUSDT | +0.085 |
| **평균** | **+0.091** |

스펙 사전폐기 임계값(|corr|≥0.7)에 전혀 못 미친다 — `oi_pt`는 평균 체결규모와 **실제로 다른
정보**다(스펙의 최대 우려였던 "동어반복" 위험은 기각). 다만 아래 §3에서 보듯, 정보가 다르다는
것이 "이 정보가 더 유용하다"는 뜻은 아니었다.

**② 구조적 발견(자체 발견 버그는 아니나 스펙 설계의 근본 한계)**: `ΔOI<0 → 0` 클리핑 때문에
`oi_pt_raw`가 항상 ≥0이고 전체 봉의 약 49~52%가 정확히 0이다(BTC 49.2%, 타 종목 48.8~51.7%).
이 점질량(point mass at 0)이 롤링 평균을 항상 0 근처로 끌어당겨 **z-score의 이론적 하한이
약 −0.90 부근에 구조적으로 갇힌다**(BTC 전체 구간 실측 min z_oi_pt = −0.8996). 스펙이 정의한
**저강도 레짐 임계값 `th_low=-1.0`은 이 데이터 구조상 사실상 도달 불가능** — 실측 결과
`z_oi_pt≤-1.0`을 만족하는 봉이 **0건**이었다(전 종목, 전체 4.6년). 스펙 스카우트 메모가 언급한
"저강도 레짐의 반대(페이드) 대조군"은 이 정의로는 애초에 검증이 불가능하다는 점을 여기서
확정한다.

**③ 전제 방향(고강도 레짐이 추세 지속에 유리한가) 간접 확인**: §3의 게이트 제거 대조군과
직접 비교가 더 명확한 증거다 — 게이트(고강도 레짐 요구) 유무만 다른 두 버전에서 **게이트가
있으면 gross PF가 뚜렷이 개선**된다(FULL 0.988→1.127, IS 0.977→1.142, OOS 1.016→1.109).
즉 "고강도 레짐에서 추세가 이어진다"는 전제 자체는 **약하게나마 실측으로 지지**되나(방향
반전 대조군도 뚜렷이 열세 — 아래 §3), 그 개선폭이 이번 비용 구조를 넘어서기엔 부족하다.

**핵심 발견**: 동일 게이트·동일 청산 로직에서 신호원만 `oi_pt` 대신 **평균 체결규모(ATS)**로
바꾼 대조군이 채택안보다 뚜렷이 우수하다 — OOS net PF 1.337(유의, t=3.258, p<0.01) vs 채택안

문제가 아니라, **OI 특유의 정보가 오히려 평균 체결규모보다 못한 신호원**이라는 뜻이다. 스펙의
핵심 가설("OI 변화라는 새로운 정보가 유용하다")이 실측으로 지지되지 않고, 오히려 스펙이
비교대상으로 지목했던 기존 계열(체결규모)이 이 백테스트 엔진·게이트 구조에서는 더 낫다는
역설적 결과다.

   `t(net,$)` 컬럼과 정확히 일치함을 대조 확인 — 직전 라운드 사례와 달리 **혼용 없음**.
9. **대표값 민감도(항목 7)**: 대안 B(블록간 차분) 재실행이 FULL/IS/OOS net PF 0.954→0.980,
   0.965→0.976, 0.939→0.986로 **소폭 개선되나 여전히 1 미만**임을 재확인 — 과거 1.355→0.944
   반전 사례와 달리 이번엔 결론이 대표값 선택에 민감하지 않다는 리포트 서술이 맞다.
