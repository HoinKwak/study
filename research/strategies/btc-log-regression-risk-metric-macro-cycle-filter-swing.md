# [스윙] BTC 로그회귀 리스크 메트릭(Cowen 스타일) 매크로 사이클 필터

- **출처**: Benjamin Cowen("Into The Cryptoverse", 대형 크립토 유튜브 채널·X 계정) 리스크 메트릭 개념. 방법론 요약 출처:

    본문 미확인** — 아래 설명은 WebSearch 검색엔진 요약 인용).
  - TradingView 오픈소스 스크립트 "Bitcoin Risk Metric II" — https://jp.tradingview.com/script/8HsNtCbh-Bitcoin-Risk-Metric-II
    (**WebFetch로 스크립트 설명 직접 확인**, 단 이 버전은 Cowen 원안과 다른 3요소 합성 변형).
  - Benjamin Cowen 본인 X 게시물(로그회귀 관련) — https://x.com/intocryptoverse/status/1537220303922679808 (URL만 확인, 본문 미열람).
- **참여지표**: Into The Cryptoverse 채널은 구독자 규모가 크고(수십만 단위, 정확한 현재 수치 미확인) 리스크 메트릭 관련 영상들이 크립토
  커뮤니티에서 반복 인용·공유되는 대표적인 매크로 사이클 지표 중 하나 — 유튜브/X에서 지속적으로 재인용되는 참여지표 기반 채택.
- **백테스트 근거**: **없음(정량 승률·PF 등 백테스트 수치 원문 미제시)**. 대신 검색 요약에 따르면 "**2013-12·2017-12·2021-04·2025-10
  4번의 사이클 고점**과 **2015-01·2018-12·2022-11 3번의 사이클 저점**을 극단 밴드 안에서 포착했다"는 **정성적 사후검증(cherry-pick 가능성
  있음, 정량 표본·오탐(false positive) 빈도 불명)** 주장이 있음 — 원문 미확인이라 액면 그대로 신뢰하지 말 것, **정량 수치 원문 미확인으로
  표기**.
- **타임프레임**: **1d(일봉), 수백~수천 봉 단위 장기 룩백** — 사이클 저점/고점을 포착하는 매크로 지표라 통상적 "스윙"(수일~수주 보유)보다
  훨씬 저빈도(연 1~4회 신호, 보유기간 수개월~1년 이상)임을 명확히 인지. 우리 태그 체계상 [스윙]으로 분류하되 **사실상 매크로 오버레이/
  포지션 사이징 필터**로 취급 권장(단독 진입/청산 트리거로 쓰기엔 신호 빈도가 너무 낮음).
- **시장/대상**: BTC 전용(원 지표가 BTC 사이클 전용으로 설계됨, 알트로 확장 시 별도 검증 필요).

## 진입 규칙 (필터/오버레이로 사용 권장, 단독 전략 아님)
- **원지표 계산(Cowen 원안, [추정] — 정확한 공식은 비공개, 검색요약 기반 근사 재구성)**:
  1. `dev_t = ln(close_t / SMA(close, 377)_t)` — 종가와 **377일 단순이동평균**의 로그 편차.
  2. 시간에 따른 체감수익(diminishing returns) 보정을 위해 `dev_t`를 시간축(예: 제네시스 이후 경과일수의 로그)에 대해 완만하게
     디트렌드(선형회귀 잔차화) — **정확한 보정식은 비공개라 우리가 재구성한 근사치**([추정]).
  3. 보정된 편차를 **전체 관측 히스토리의 최소~최대 구간으로 0~1 정규화**: `risk_t = (dev_t - hist_min) / (hist_max - hist_min)`.
- **매크로 롱 바이어스(축적)**: `risk_t < 0.4` → 신규 롱 허용/비중 확대, 숏 신규진입 금지.
- **매크로 숏 바이어스(분산/경계)**: `risk_t > 0.7` → 신규 숏 허용/롱 비중 축소, 롱 신규진입 금지(또는 트레일링 타이트닝).
- **중립구간(0.4~0.7)**: 매크로 필터로서는 무신호 — 하위 타임프레임 전략(예: 우리 scalp15m)이 자유롭게 양방향 트레이드하도록 허용.

## 청산 규칙
- 이 지표 자체는 **진입/청산을 직접 실행하지 않고 게이팅(허용/차단)만 하는 필터**로 설계 권장.
- 만약 단독 매크로 포지션으로 쓴다면: risk가 0.4 아래로 진입해 롱을 잡았을 경우, **risk_t > 0.7 도달 시 전량 청산**(또는 반대로 대칭).
- 시간 청산: 없음(사이클 지표 특성상 보유기간이 본질적으로 수개월~1년 단위).

## 파라미터
- sma_period=377일 (Cowen 원안 근사값, 원문에 명시된 것으로 검색 요약에 언급됨 — 정확도 미검증)
- risk_low_threshold=0.4 (범위 0.3~0.45, 축적구간)
- risk_high_threshold=0.7 (범위 0.65~0.8, 분산구간)
- normalization_window=전체 히스토리(범위: 최소 2~3 사이클치 데이터, BTC는 2013년 이후 일봉 필요)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 377일 SMA, 로그가격 편차, (선택)시간축 디트렌드용 선형회귀. 계산 자체는 단순.
- 주의: **정규화(min-max)에 매우 긴 히스토리(수년~십수년 일봉)가 필요** — 바이낸스 선물(USDT-M)은 BTC 상장이 2019년 9월이라
  377일 SMA는 계산되나, **Cowen 원안은 2013년 이후 현물 데이터를 씀** → 정규화 min/max 기준이 달라질 수 있어 우리가 재현하면
  Cowen이 게시하는 값과 다를 수 있음(현물 장기 데이터로 정규화하고 선물가로 신호만 적용하는 방식 검토 필요, `data.binance.vision`
  현물 미러로 장기 BTC 일봉 확보 가능).

## 스카우트 메모
- **강점**: 크립토 커뮤니티에서 가장 널리 참조되는 매크로 사이클 지표 중 하나로 참여지표(반복 인용)가 매우 높음. 우리 봇처럼 단타
  위주인 시스템에 **매크로 리스크 오프/온 필터**를 하나 얹으면(예: risk>0.8인 극단 과열구간에서는 롱 신규진입 자체를 금지) 대형 사이클
  고점 근처의 대규모 손실을 줄이는 **리스크 관리 오버레이**로서 가치가 있을 수 있음(단독 알파 전략이 아니라 필터로서의 가치).
- **의심점**: ① Cowen의 정확한 정규화·디트렌드 공식은 비공개라 우리 구현은 **근사치([추정])**이며 원 지표와 값이 다를 수 있음.
  ② "4개 고점·3개 저점 전부 포착"이라는 주장은 사후적(hindsight)이고 표본이 7개 사건뿐이라 통계적 유의성 낮음 — 정량 백테스트(예:
  risk>0.7 구간에서 숏 진입 시 실제 승률·PF)는 원문에 없어 완전히 미검증. ③ 신호 빈도가 극히 낮아(연 0~수회) 우리 백테스트 프레임워크의
  "표본 수 확보" 기준을 만족시키기 어려움(다른 FAIL 판정 전략들처럼 표본부족으로 HOLD 판정 가능성 높음).
- **우리 슬리브와의 관계**: 단독 전략이 아니라 **기존 scalp15m 위에 얹는 매크로 리스크 게이트**로 검토하는 것을 권장(예: risk 극단
  구간에서 레버리지 축소·포지션 사이즈 축소). 신규 슬리브로서의 백테스트 우선순위는 낮음(신호 빈도 부족), 다만 **리스크 관리 정책
  아이디어**로서는 별도 논의 가치 있음.
