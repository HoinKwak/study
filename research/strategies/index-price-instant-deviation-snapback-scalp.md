# [단타] 인덱스가격(Index Price) 즉시괴리 스냅백 스캘프

- **출처**: 데이터 필드 근거 — https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Index-Price-Kline-Candlestick-Data (바이낸스 공식, `indexPriceKlines` 정의: 스팟 바스켓 가중평균으로 산출되는 **인덱스가격**의 캔들 시계열) /
  개념 배경(정성적) — https://www.binance.com/en/support/faq/detail/360033525791 (바이낸스 공식, 마크가격·인덱스가격·프리미엄인덱스의 관계 설명, 급격한 테이커 매수/매도 쏠림이 무기한 last price를 인덱스에서 순간적으로 크게 이탈시켰다가 되돌아오는 현상을 정성적으로 설명).
  **정확한 이 스캘프 규칙(임계값·타임프레임)은 스카우트가 위 두 원문의 개념을 조합해 자체 설계함 — 외부에 이 정확한 백테스트는 존재하지 않으며 지어내지 않음.**
- **참여지표**: - (자체 설계). "인덱스 이탈 후 스냅백"이라는 개념 자체는 마켓메이커·차익거래 커뮤니티에서 통용되는 상식이나, 이 정확한 규칙의 SNS 참여지표는 없음.
- **백테스트 근거**: **없음(자체 설계, 정량 근거 지어내지 않음)**.
- **타임프레임**: 1m 신호 / 5m 확인.
- **시장/대상**: BTC·ETH·BNB·SOL·XRP·DOGE·ADA 무기한. `indexPriceKlines` 1m 덤프가 7종목 모두 `data.binance.vision`에 2019-12-23부터 존재함을 직접 다운로드로 확인(2026-08-09, `BTCUSDT-1m-2024-06-01.zip` 등, 컬럼 `open_time,open,high,low,close,volume,close_time,quote_volume,count,taker_buy_volume,taker_buy_quote_volume,ignore` — 인덱스는 실거래가 아니라 volume/count는 0/상수 placeholder이므로 **close 가격만 사용**).

## 진입 규칙
- 기존 보유 `premium-index-zscore-mean-reversion-scalp.md`와의 차이를 명시: 그 스펙은 바이낸스가 **평활화(smoothing)해 산출한 프리미엄인덱스**(`premiumIndexKlines`, "임팩트중간가-인덱스가"의 완충된 값)를 5~15m봉 200개 롤링 z-score로 관찰하는 **느린(수십 시간 스케일) 평균회귀**다. 본 스펙은 **평활 이전의 원시 무기한 체결가(perp klines close)와 원시 인덱스가(indexPriceKlines close)의 순간 괴리**를 1m 단위로 보고, **수 분~수십 분 내** 되돌림을 노리는 **훨씬 빠른 스케일**의 별개 메커니즘이다.
- 괴리율 `dev = (perp_close_1m - index_close_1m) / index_close_1m`.
- 괴리율의 최근 `dev_window`=60분 롤링 표준편차 대비 현재 값의 배수(`dev_mult = dev / rolling_std(dev, 60)`)를 계산.
- 롱(순간 저평가 스냅백): `dev_mult <= -3.0`(퍼프가 인덱스보다 비정상적으로 급락 — 대량 시장가 매도·청산 캐스케이드로 인한 순간 미끄러짐 추정) **AND** 직전 1분봉 거래량이 최근 60분 평균 대비 `vol_spike_mult`=4배 이상(실제 체결 쏠림 확인, 데이터 지연/오류로 인한 가짜 괴리 배제) → 롱.
- 숏(순간 고평가 스냅백): `dev_mult >= +3.0` **AND** 동일 거래량 조건 → 숏.

## 청산 규칙
- 익절: `dev`가 0(인덱스와 재수렴) 도달 시 또는 진입가 대비 `tp_pct`=0.3% 중 먼저 도달하는 쪽.
- 손절: 진입가 대비 `sl_pct`=0.5%(스냅백이 아니라 추세 지속으로 판명 시 빠른 손절).
- 시간 청산: `max_hold`=15분 내 미도달 시 강제청산(스냅백이 예상대로면 대부분 수 분 내 해소되어야 함 — 15분 넘게 지속되면 "노이즈"가 아니라 "새 정보"로 재해석).

## 파라미터
- dev_window=60분 (범위 30~120)
- dev_mult_th=3.0 (범위 2.0~4.0)
- vol_spike_mult=4.0 (범위 3.0~6.0)
- tp_pct=0.3% (범위 0.2~0.5%)
- sl_pct=0.5% (범위 0.3~0.8%)
- max_hold=15분 (범위 10~30)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 없음에 가까움 — `indexPriceKlines`(신규 로더 필요, 컬럼은 캔들과 동일 포맷이라 기존 klines 파서 재사용 가능) close 시계열 + 기존 perp klines close·volume.
- 주의: **완전히 바이낸스 REST/덤프 단일 소스**(오더북·틱·실시간청산 불필요). `indexPriceKlines`는 볼륨이 항상 0인 합성 시계열이므로 이 컬럼으로 필터링하면 안 됨(perp klines의 거래량 사용). 1m 해상도라 백테스트 데이터량이 큼(7종목×연간 1m봉 ≈ 종목당 525,600행) — 다운로드·저장 비용 고려 필요.

## 스카우트 메모
- **예상 표본 빈도**: [추정] `dev_mult≥3.0`은 60분 표준편차 기준 3σ 사건이라 정규분포 가정 시 드물지만, 인덱스-퍼프 괴리는 팻테일(청산 캐스케이드)이 잦아 실제로는 이보다 훨씬 자주 발생할 가능성 있음 — 과거 라운드(Hikkake)에서 "표본 정의가 느슨해 예상보다 20~100배 신호가 쏟아진" 전례가 있으므로, 백테스트 착수 시 **1차로 트리거 횟수만 먼저 세어 예상(종목당 연 수십~수백건) 대비 얼마나 벗어나는지 확인**을 최우선으로 권고.
- **gross 엣지 가설**: 인덱스가격은 스팟 바스켓 가중평균이라 무기한 last price보다 노이즈가 적고 조작 저항성이 큼(바이낸스가 청산가·마크가 산출에 인덱스를 쓰는 이유). 퍼프가 인덱스에서 급격히 이탈하는 것은 대부분 "일시적 유동성 소진"(청산 캐스케이드·대량 시장가 주문)이지 "새로운 정보"가 아니므로 재수렴 압력이 구조적으로 존재한다는 논리 — 다만 이 논리가 수수료(왕복 0.14%)를 이길 만큼 크고 빠른지는 미검증.
- **엣지 대비 거래빈도**: 익절폭 0.3%가 수수료(0.14%) 대비 얇아 **손익비가 타이트함** — gross PF가 아주 높지 않으면 net에서 바로 잠식될 위험이 이번 라운드 교훈(OI컨퍼메이션 gross1.395인데도 연200건에 net 0.688로 무너짐)과 동일 패턴으로 재현될 수 있음. 익절폭을 좁게 잡은 이유(스냅백 자체가 작은 괴리)와 상충되므로 채택 시 파라미터 스윕에서 tp_pct를 충분히 넓게도 테스트 권고.
- **독립성/클러스터링 위험**: 청산 캐스케이드는 시장 전체적 이벤트라 **7종목이 동시에 트리거될 가능성이 매우 높음**(과거 프리미엄인덱스 모멘텀 스펙에서 7종목 동시진입일 13.3% 확인된 것과 동일 메커니즘) — 백테스트 시 이벤트(분) 단위 클러스터링 진단 필수.
- **7종목 신호 충분성**: 데이터 존재는 7종목 모두 확인됐으나(위 참조), 알트(DOGE·ADA 등)는 인덱스 바스켓 자체의 유동성이 얇아 인덱스 자체가 더 출렁일 수 있어 "괴리"의 의미가 BTC·ETH와 다를 수 있음(신호 품질 종목별 편차 우려).
- **강점**: 완전 신규 데이터 소스(`indexPriceKlines`)를 처음 실사용하는 스펙 — 향후 다른 베이시스 계열 재검증에도 재사용 가능. 시장중립적 되돌림 논리라 방향성 베팅이 아님.
- **의심점**: tp/sl 폭이 수수료 대비 얇아 net에서 잠식될 위험이 가장 큰 약점. 1m 해상도 데이터 인프라 구축 비용도 상대적으로 큼(다른 스펙 대비 신규 로더+대용량 다운로드 필요).
- **우리 단타 슬리브와의 관계**: 라이브 `scalp15m`(볼린저 이탈+거래량+OI, 추세추종형 돌파)과 정반대 성격(평균회귀형, 훨씬 짧은 보유시간) — 신호 상관 낮을 가능성. 기존 `premium-index-zscore-mean-reversion-scalp.md`(같은 "인덱스 대비 괴리" 대주제, 5~15m·평활 프리미엄·수십시간 스케일)와는 데이터 필드·시간축이 명확히 달라 중복 아님.
