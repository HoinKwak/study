## 패턴 정의 (Scott Carney 표준 비율, GitHub 저장소·TradingView 스크립트 대조 확인)
- 5개 스윙 포인트 X→A→B→C→D를 프랙탈 지그재그(ZigZag)로 추출(고저 반전폭 임계치 이상인 점만 스윙으로 인정).
- **Gartley**: B = XA의 **0.618** 되돌림, D = XA의 **0.786** 되돌림(=PRZ, Potential Reversal Zone).
- **Bat**: B = XA의 **0.382~0.5**, D = XA의 **0.886**.
- **Butterfly**: B = XA의 **0.786**, D = XA의 **1.27** 확장.
- **Crab**: B = XA의 **0.382~0.618**, D = XA의 **1.618** 확장.
- (참고, 본 스펙 범위 밖) Cypher/Shark는 GitHub·GBB 양쪽에 정의돼 있으나 본 스펙은 4대 주요 패턴만 채택.
- 각 비율에 **허용오차 ±3~5%**(tolerance band)를 둬 정확히 일치하지 않아도 패턴으로 인정. GBB 스크립트는 Strict/Standard/Lenient 3단계 프리셋을 제공(Standard = Carney 공식 허용오차).
- Bullish 패턴(롱 후보): X가 저점, A가 고점, ..., D가 저점(패턴 저점에서 반전 기대). Bearish는 대칭.

## 진입 규칙
- 롱: Bullish XABCD 패턴의 **D점 완성 직후**(가격이 PRZ 구간에 도달하고 되돌아 나오는 확인봉 종가 기준) + 확인 캔들 반전 신호(D점 봉이 아래꼬리 우세 또는 다음 봉이 D점봉 고가 상향 돌파) 동시 충족 시 진입.
- 숏: 대칭(Bearish 패턴, D점이 고점).
- (선택 필터) D점에서 RSI(14) 다이버전스(가격 신저점, RSI는 미갱신) 동반 시 신뢰도 가점 — Carney 방법론에서도 보조 확인으로 권장되는 요소.

## 청산 규칙
- 손절: X점 바로 바깥(X를 완전히 무효화하는 수준) — 통상 `D ± (XA 폭 × 0.1~0.15)` 버퍼로 근사.
- 익절: 1차 목표 = C점 되돌림(CD의 **0.382**), 2차 목표 = **A점 재도달**, 3차(선택) = XA의 **1.27~1.618 확장**(반대 방향).
- 시간/조건 청산: 진입 후 N봉(예 30봉, 4h 기준 5일) 내 1차 목표 미도달 시 타임아웃 청산 — [제안] 안전장치(원문에 명시 없음).

## 파라미터
- zigzag_pct_threshold=3.0% (범위 1.5~5.0%, 스윙포인트 인정 최소 반전폭 — 4h 기준)
- ratio_tolerance=5% (범위 3~8%, Standard 프리셋 근사)
- rsi_divergence_filter=off (기본 비활성, on 시 가점만 부여)
- stop_buffer_frac=0.10 (XA폭 대비, 범위 0.05~0.20)
- tp1_ratio=0.382 (CD 되돌림), tp2=A점, tp3=1.27 (XA 확장)
- timeout_bars=30 (4h 기준, 범위 20~60)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 지그재그(ZigZag, OHLC 고저로 계산), 피보나치 비율 계산, RSI(선택). **전부 바이낸스 REST 캔들로 충족.** 오더북·틱·실시간청산 불필요.
- 난이도: **높음**. 지그재그 임계치 선택에 결과가 매우 민감(과최적화 위험 큼), 4점 동시 비율 매칭 로직이 볼린저/EMA류 대비 구현·검증 부담이 훨씬 큼. 룩어헤드 방지 특히 중요 — ZigZag는 본질적으로 미래 봉을 봐야 마지막 스윙포인트 확정이 되므로, "확정된 스윙만 사용"(최신 미확정 다리는 신호에서 제외)하는 처리가 필수.

## 스카우트 메모
- 강점: 참여지표(TradingView 1.1K 즐겨찾기·11,610 조회)가 이번 라운드 발굴 중 상위권. 손절이 X점 기준으로 명확하고 목표가 다단계(C/A/확장)라 **R 배수가 크고 빈도 낮은 스윙형**이라는 점에서 스윙 슬리브 요구에 부합.
- 의심점(강한 회의): (1) **실측 백테스트가 원문 확인됐으나 결과가 부정적**(PF 0.89, 승률 42.9%, 총수익 −0.05%) — 다만 n=7로 통계적 유의성 없음, "패턴이 안 통한다"도 "통한다"도 결론 못 냄. (2) 지그재그 임계치·허용오차 선택에 결과가 극도로 민감해 **과최적화 위험이 이번에 다룬 전략 중 가장 큼**. (3) 구현 복잡도가 높아 버그 유입 가능성 큼 — 반드시 단위테스트(알려진 과거 하모닉 사례로 패턴 탐지 검증)를 거친 뒤 백테스트해야 신뢰 가능.
- 우리 단타 슬리브와의 관계: 무관(스윙 전용). 기존 `fibonacci-golden-pocket-pullback`(단순 되돌림)과 개념적으로 인접하지만, 하모닉은 4점 동시 비율 매칭이라는 훨씬 엄격한 구조라 **중복이 아닌 상위호환/보완 관계**. 다만 위 부정적 실측 결과와 구현 난이도를 감안하면 **백테스트 우선순위는 낮음**(구현 비용 대비 기대값이 불확실).
