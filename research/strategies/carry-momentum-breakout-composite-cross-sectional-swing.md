# [스윙] 캐리(펀딩)+모멘텀+브레이크아웃 가중합성 횡단면 팩터 전략 (무기한 선물 상위30)

- **출처**: Ryan Chan(analytic-musings.com), "Crypto Stat Arb I: Quantifying & Combining Alphas"
  https://analytic-musings.com/2024/03/10/crypto-stat-arb-I/ (WebFetch로 원문 확인) / 코드·후속편:
  GitHub https://github.com/ryanczm/Crypto-Stat-Arb ("Cross-sectional/time series carry/momentum/
  breakout Crypto stat arb strategy on perps") — 바이낸스 무기한 선물 **유동성(롤링거래량) 상위 30개
  종목, 2019~2024** 데이터로 신호 리서치 및 백테스트(rsims 프레임워크, 거래비용·트레이드버퍼 반영).
- **참여지표**: - (개인 퀀트 블로그+GitHub, SNS 참여지표 미집계. 단 시리즈 2편(Part II)이 실제 코드로
  백테스트까지 완결한 실증형 리서치라 신뢰도 근거로 채택)
- **백테스트 근거**: **신호 품질 근거는 원문 확인, 최종 포트폴리오 성과 수치는 검색으로 확인 못 함
  (정직 표기)**. 원문(WebFetch)에서 확인된 내용:
  - 각 팩터를 **일자 횡단면 Z-score → 십분위(decile) 버킷화** 후 IC(정보계수)·십분위 평균수익률로
    품질 평가.
  - **캐리(펀딩) 팩터가 IC가 가장 높고 시간에 걸쳐 "끈적임(sticky)"**(예측력 지속) 있음. **브레이크아웃
    팩터는 시계열 관점 IC가 강하나 빠르게 감쇠**(추세 초입에만 유효). **모멘텀 팩터는 셋 중 IC가
    가장 낮음**. 브레이크아웃은 모멘텀과 상관 있으나 캐리는 브레이크아웃·모멘텀과 거의 무상관
    (분산 효과 존재).
  - 결합 시 **하드코딩 가중치 캐리 0.5 / 모멘텀 0.2 / 브레이크아웃 0.3**을 사용해 일별 포트폴리오
    비중 산출.
  - **⚠️ Part II(백테스트, rsims 기반)의 최종 샤프비율·수익률·MDD 수치는 검색·WebFetch로 확인하지
    못함** — GitHub 저장소의 노트북(`stat-arb-backtest.ipynb`)에 있을 것으로 추정되나 원문 직접
    확인 실패. **이 수치들은 절대 지어내지 않고 "미확인"으로 명시.** 채택 시 반드시 우리 프레임워크로
    처음부터 백테스트 필요.
- **타임프레임**: 일봉(1d) 리밸런스(원문 캐리=24h 펀딩, 모멘텀=10일 수익률, 브레이크아웃=20일 신고가
  근접도 — 전부 일봉 기준 팩터).
- **시장/대상**: 바이낸스 무기한 선물 **유동성(롤링거래량) 상위 30개 종목**(원문 기준, 우리 동적
  유니버스 $10M+ 필터와 유사 개념).

## 진입 규칙
- **모멘텀 팩터**: `momentum = (close_t − close_{t−10}) / close_{t−10}` (10일 수익률), **1봉 지연
  (lag 1)** 후 사용(당일 미래데이터 참조 방지). 횡단면(그날 유니버스 전체) Z-score화 후 십분위 버킷.
- **캐리 팩터**: 최근 **24시간 펀딩비**, 1봉 지연 후 사용. 횡단면 Z-score화 후 십분위 버킷.
  (양의 펀딩=롱 과열/캐리 비용 → 통상 숏 유리 방향, 원문 부호 정의는 십분위 버킷 순서로 처리)
- **브레이크아웃 팩터(시계열)**: `breakout = 9.5 − (20일 신고가 경신 이후 경과일수)`, 1봉 지연 후
  사용. 값이 클수록(경과일수가 적을수록) 최근 신고가에 근접 — 추세 초입 근접도를 나타냄.
- **팩터 결합**: 캐리·모멘텀은 `(십분위값 − 5.5)`로 중심화(−4.5~+4.5 범위), 브레이크아웃은
  `브레이크아웃값 / 2`로 스케일링. 최종 신호 = `0.5×캐리_중심화 + 0.2×모멘텀_중심화 + 0.3×브레이크아웃_스케일`.
- 롱: 위 결합 신호가 유니버스 내 상위권(예: 상위 20~30%)인 종목.
- 숏: 결합 신호가 하위권인 종목(무기한 시장이므로 대칭 공매도 가능).
- **비중배분**: 매일 종가 기준 결합 신호 절대값으로 정규화해 포트폴리오 비중 합이 1이 되도록 배분
  (롱숏 합산 그로스 100% 기준, 원문 그대로).

## 청산 규칙
- 익절/손절: 개별 트레이드 단위 TP/SL 없음(팩터 포트폴리오 방식) — **매일 리밸런스 시 팩터 재계산**해
  순위가 바뀌면 비중 자동 조정.
- 시간/조건 청산: 없음(연속 리밸런스). 원문은 회전율 억제를 위해 **트레이드 버퍼 휴리스틱**(포지션
  변화가 임계치 이하면 리밸런스 스킵) 적용 — 정확한 버퍼 임계값은 원문에 수치로 없음([설계값] 필요).

## 파라미터
- momentum_lookback=10일 (원문, 범위 5~20일)
- carry_lookback=24h 펀딩 (원문, 고정)
- breakout_lookback=20일 신고가 기준, breakout_const=9.5 (원문 그대로)
- weight_carry=0.5, weight_momentum=0.2, weight_breakout=0.3 (원문 하드코딩값, 범위 재검증 필요 —
  원문도 "동적 가중치(회귀 기반 기대수익 추정)와 비교"를 후속 과제로 언급함)
- universe_size=30 (원문, 유동성 상위)
- rebalance_freq=1d
- trade_buffer=[설계값 필요, 원문에 정확한 수치 없음]

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 10일 수익률(종가만), 24h 펀딩비(바이낸스 REST `fundingRate` 엔드포인트), 20일 신고가
  경과일수(rolling max 위치 추적). **전부 바이낸스 REST(캔들+펀딩비)로 완전 충족** — 오더북/틱/외부
  데이터 불필요한 것이 이 라운드 발굴분 중 가장 깔끔한 데이터 요구사항.
- 주의: 유동성 상위 30개 종목의 캔들+펀딩비를 매일 동시 조회·랭킹해야 함 — 데이터는 충족되나
  **다수 심볼 동시 롱숏 포지션 관리(포트폴리오 엔진)**가 필요해 기존 단일 슬리브 구조와 다름
  (위 돈치안 앙상블 전략과 동일한 인프라 제약).

## 스카우트 메모
- 강점: **캐리·모멘텀·브레이크아웃 각 팩터의 정의·결합공식·가중치가 원문에 정확한 수치로 공개**돼
  있어(하드코딩 가중치까지) 이 라운드 발굴분 중 **재현성이 가장 높은 스펙**. 캐리(펀딩) 팩터를
  주력(가중치 0.5)으로 쓴다는 점이 독특 — 기존 보유 펀딩 전략들(`funding-rate-extreme-contrarian`,
  `funding-oi-price-triple-confirm-carry-momentum-swing` 등)은 펀딩을 단독 또는 보조 필터로 쓰는
  반면, 이 전략은 **펀딩을 3팩터 중 최대 가중치의 핵심 알파**로 명시적으로 사용한다는 점에서 구조가
  다름.
- 의심점: **최종 백테스트 성과 수치(샤프·수익률·MDD)를 원문에서 직접 확인하지 못함** — 신호 리서치
  (IC·십분위 분석)만 확인됐고 실제 포트폴리오 성과는 미확인 상태로 채택. 채택 전 반드시 GitHub
  저장소의 백테스트 노트북을 직접 열람하거나 우리 프레임워크로 처음부터 검증 필요. 하드코딩
  가중치(0.5/0.2/0.3)는 저자도 "동적 가중치 대비 단순 버전"이라 명시해 최적화 여지가 있음.
- 우리 슬리브와의 관계: 포트폴리오형이라 인프라 제약은 위 돈치안 앙상블과 동일. 신호 메커니즘은
  **명확히 다름**(3팩터 가중합성 vs 단일 시계열 추세신호) — 포트폴리오 엔진 구축 시 두 전략을
  독립적으로 비교하거나 앙상블(팩터 오브 팩터)도 시도 가치 있음.
