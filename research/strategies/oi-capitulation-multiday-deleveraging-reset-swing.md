# [스윙] 다일간 OI 자본항복(캐피튤레이션) 디레버리징 리셋 반전

- **출처**: 개념 프레임 — https://www.ainvest.com/news/role-leverage-liquidation-cascades-crypto-derivatives-markets-2602/ (레버리지 사이클: OI 누적→펀딩 쏠림→청산 캐스케이드→OI 리셋의 전형적 국면 서술, **WebFetch 403으로 원문 직접 열람 실패, WebSearch 스니펫만 확인**) /
  https://cryptopotato.com/not-the-bottom-yet-cryptoquant-data-exposes-bitcoins-brutal-deleveraging/ (CryptoQuant 데이터 인용 기사, "OI가 900억→445억 달러로 급감=레버리지 청산으로 강제매도 연료 소진" 서술, **WebFetch 503으로 원문 직접 열람 실패, WebSearch 스니펫만 확인**) /
  기존 보유 스펙 `oi-roc-price-divergence-squeeze-reversal-scalp.md`(15m/1h 스캘프, OI ROC -5%/20봉 임계치)와 **동일 데이터축(OI+가격 다이버전스)이지만 규모·시간축·구조가 명확히 다른 스윙 버전** — 아래 스카우트 메모 참조.
- **참여지표**: - (전문 데이터 블로그·WebFetch 실패로 원문 직접 검증 못함, 스니펫 수준 신뢰도)
- **백테스트 근거**: **없음(개념 기반, 정량 수치 지어내지 않음)**. 두 출처 모두 WebFetch가 403/503으로 차단돼 원문을 직접 열람하지 못했음을 **정직하게 명시**. WebSearch 요약 수준에서 확인되는 것은 "OI 급감(디레버리징)=강제매도 연료 소진→시장이 더 단단해짐"이라는 **정성적 서술뿐**, 승률·PF 등 수치는 전무. **채택 전 자체 백테스트 필수, 최우선순위 아님.**
- **타임프레임**: 4h 봉으로 신호 산출·관리 (OI/가격 다일간 변화율은 4h 이상에서 안정적으로 측정 가능, 1h 이하는 노이즈로 오탐 위험)
- **시장/대상**: BTC·ETH·시총상위 알트 무기한(OI 데이터가 유동성 있게 잡히는 종목)

## 진입 규칙
- **1단계(셋업 플래그)**: 최근 `oi_window`=3일(4h×18봉) 동안의 OI 변화율과 가격 변화율을 계산.
  - **롱 셋업**: `가격 3일 ROC ≤ -price_drop_threshold`(예 -10%) **AND** `OI 3일 ROC ≤ -oi_drop_threshold`(예 -15%) → "롱 강제청산 캐스케이드"로 판정, 향후 `confirm_window`=6봉(24h) 동안 반전 확인 대기 플래그 활성화.
  - **숏 셋업**: `가격 3일 ROC ≥ +price_rise_threshold`(예 +10%) **AND** `OI 3일 ROC ≤ -oi_drop_threshold`(예 -15%) → "신규 매수세 없는 순수 숏스퀴즈"(OI가 줄면서 가격만 오름=숏 커버링 랠리, 지속력 의심)로 판정.
- **2단계(트리거 확인)**: 플래그 활성 후 `confirm_window` 이내에,
  - 롱: OI 24h ROC가 처음으로 **≥ 0%**로 전환(추가 청산 소진 확인) **AND** 해당 4h봉 종가가 직전 4h봉 고가 상향 돌파(반등 모멘텀 확인) → **롱 진입**.
  - 숏: 해당 4h봉 종가가 직전 4h봉 저가 하향 이탈(랠리 모멘텀 꺾임 확인) → **숏 진입**.
  - `confirm_window` 내 트리거가 발생하지 않으면 셋업 폐기(신규 진입 없음).

## 청산 규칙
- 익절: ATR(14,4h) × `atr_trail_mult`=3.0 트레일링 스톱(신고가/신저가 갱신 시 갱신), 또는 R:R `rr_target`=2.5 도달.
- 손절: 1단계 셋업 구간의 극값(롱은 3일 구간 최저가, 숏은 3일 구간 최고가) ± `stop_buffer_pct`=1.0%.
- 시간 청산: 진입 후 `max_hold_bars`=90봉(4h≈15일, 범위 60~120) 초과 시 강제청산.

## 파라미터
- oi_window=3일 (범위 2~5일, 4h 기준 12~30봉)
- oi_drop_threshold=15% (범위 10~25%)
- price_drop_threshold=10% (롱 트리거, 범위 7~15%)
- price_rise_threshold=10% (숏 트리거, 범위 7~15%)
- confirm_window=6봉 (24h, 범위 4~12봉)
- atr_trail_mult=3.0 (범위 2.0~4.0)
- stop_buffer_pct=1.0% (범위 0.5~2.0%)
- rr_target=2.5 (범위 2.0~3.0)
- max_hold_bars=90 (4h 기준, 범위 60~120)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: OI 시계열(`/fapi/v1/openInterestHist`, 이미 `scalp.py`에서 사용 중이라 인프라 재사용 가능) + 가격 ROC + ATR. 오더북/틱/실시간청산 스트림 불필요 — **OI 급감을 "청산의 대리지표"로 간접 추정**하는 한계는 기존 OI 다이버전스 스펙들과 동일.
- 주의: 장기 OI 백테스트는 `data.binance.vision/data/futures/um/daily/metrics/` 덤프 필요(기존 OI 관련 스펙과 동일 인프라). 3일치 대규모 OI 급락(-15%)은 시장 전체가 동시에 겪는 매크로 이벤트(예: 2022-05 루나사태, 2022-11 FTX, 2024-08 글로벌 매도)에 다수 종목이 동시 반응하므로, **여러 알트에서 발생한 신호가 서로 독립적이지 않고 상관돼 있을 가능성**(사실상 소수의 매크로 이벤트가 표본을 부풀릴 위험) — 표본 수를 셀 때 "고유 이벤트 수"와 "종목×이벤트 조합 수"를 구분해 보고할 것.

## 스카우트 메모
- **강점**: "레버리지 사이클(누적→쏠림→캐스케이드→리셋)"이라는 파생상품 업계에서 반복적으로 관찰되는 구조적 프레임을 규칙화. 기존 `oi-roc-price-divergence-squeeze-reversal-scalp.md`(15m/1h, OI ROC -5%/20봉≈5시간, 최대보유 2시간)와 **규모·시간축이 완전히 다름**(본 스펙은 3일간 -15% 이상의 **대형 디레버리징 이벤트**만 포착, 최대보유 15일) — 스캘프 버전이 "일상적 소규모 스퀴즈"를 잡는다면 본 스펙은 "시장을 흔드는 대형 이벤트"를 잡는 구조로 상호보완적(둘 다 채택 시 서로 다른 국면에서 발화해 겹칠 가능성 낮음).
- **의심점**: (1) 정량 백테스트 근거가 전무(WebFetch 접근 실패로 원문조차 확인 못함) — 순수 개념 기반, 최우선순위 아님. (2) **예상 표본 빈도가 가장 큰 리스크**: -15%/3일 OI 급락은 진짜 대형 이벤트 기준이라 종목당 연 2~5회 수준일 수 있고, 이런 이벤트는 시장 전체에 동시다발적으로 퍼지는 경향이 있어(위 데이터 요구 항목 참조) **"고유 독립표본"은 지난 라운드 HOLD 2건(토큰언락 16건·ETF유출 7건)과 유사하게 얇아질 위험**이 있음. 백테스트 착수 시 임계치를 완화한 버전(예: -10%/2일)도 병행 스윕해 표본 확보 여부를 가장 먼저 확인할 것. (3) "OI 급감=청산"이라는 해석은 실제 청산 스트림 데이터가 아닌 간접 추정.
- **우리 슬리브와의 관계**: 독립적 신규(같은 OI 데이터를 쓰지만 스캘프 버전과 시간축·규모가 달라 상호배타적이지 않음). 지난 라운드 HOLD 2건(토큰언락 페이드·ETF유출 컨트래리언)이 저빈도 문제로 최종 통과하지 못한 전례를 감안, **이 전략도 착수 시 가장 먼저 "탐지된 이벤트 수"를 세어 수십 건 미만이면 조기에 저우선순위로 재분류**할 것을 권고.
