# [스윙] 이더리움 가스비 네트워크혼잡 레짐 게이트 + ETH 추세추종 (온체인 외부데이터)

- **출처**: 데이터 필드 근거 — Etherscan 공식 API `stats/dailyavggasprice`
  (https://docs.etherscan.io/etherscan-v2/api-endpoints/stats-1#get-daily-average-gas-price, 일별 평균
  가스가격, gwei 단위, 2015-08~현재). **정확한 이 규칙(가스비 레짐→ETH 추세추종)은 스카우트가 자체
  설계**함 — "가스비 급등=네트워크 수요 급증=리스크온 신호" 또는 "가스비 급등=온체인 혼잡=단기 스트레스"
  라는 개념 자체는 이더리움 커뮤니티·온체인 분석 계정(예: @econoar, @ChainLinkGod 류 온체인 지표 트위터)
  에서 자주 회자되나, 이 정확한 규칙의 SNS 참여지표는 집계 못함. 외부에 이 정확한 백테스트는 존재하지
  않으며 지어내지 않음.
- **참여지표**: - (자체 설계).
- **백테스트 근거**: **없음(자체 설계, 정량 근거 없음)**.
- **타임프레임**: 가스비 레짐 — 일간 / ETH 4h 진입·확인.
- **시장/대상**: **ETH 단일종목 한정**(가스비는 이더리움 메인넷 고유 지표라 다른 체인 코인에 적용 근거
  없음 — BTC·SOL 등은 가스비 개념 자체가 다르거나 없음).

## 진입 규칙
- 데이터: Etherscan API V2 `stats/dailyavggasprice` (⚠️구버전 V1 엔드포인트는 2026-08-25 curl 확인 결과
  "deprecated" 응답 — **V2로 전환 필요, 무료지만 회원가입 후 발급받는 API 키가 필수**임을 직접 확인.
  기존 스펙 대부분이 완전 무인증 CSV/curl인 것과 달리 **이 스펙만 신규 API 키 발급이 필요한 인프라
  의존성**이 있음, 아래 "코딩 난이도" 참조).
- `gas_z(t) = (gas(t) - rolling_mean(gas, 30일)) / rolling_std(gas, 30일)` (30일 롤링 z-score, 데미닝
  필수 — 과거 인덱스가격 스냅백 스펙에서 데미닝 누락으로 신호 과다 발생한 전례를 반영).
- **레짐**: `gas_z(t) >= +2.0`(가스비 급등=온체인 혼잡·수요 급증) → 다음 4h 확인봉에서 ETH가 EMA20(4h)
  위에 있으면 **롱**(수요 급증이 실수요 랠리와 동행), EMA20 아래면 **숏**(혼잡이 패닉/청산 캐스케이드와
  동행 — 방향 미확정이므로 EMA 위치로 방향을 정하는 것 자체가 이 스펙의 핵심 가설, [설계판단]).
- `gas_z(t) <= -1.5`(가스비 급락=네트워크 활동 위축)는 진입 신호로 쓰지 않음(관찰용 대조군으로만 병행
  백테스트, [설계판단]).

## 청산 규칙
- 익절: ATR(4h,14)×2.5 트레일링.
- 손절: 진입가 ∓ATR(4h,14)×1.5.
- 시간 청산: `max_hold`=5일(가스비 급등은 통상 수일 내 해소되는 단기 이벤트로 가정).

## 파라미터
- gas_z_window=30일 (범위 14~60)
- gas_z_th=2.0 (범위 1.5~3.0)
- ema_len=20 (4h, 범위 10~30)
- atr_stop_mult=1.5, atr_trail_mult=2.5
- max_hold=5일 (범위 3~10)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: Etherscan API V2 일별 평균 가스가격(**무료지만 신규 API 키 발급 필요** — 기존 대부분 스펙의
  완전 무인증 패턴과 다름, `.env`에 신규 자격증명 추가 필요) + ETH 4h klines(EMA·ATR). 오더북/틱/실시간
  청산 불필요.
- 주의: **키 발급이라는 신규 인프라 의존성**이 이 스펙의 최대 실행 장벽 — 발급 자체는 무료·즉시지만,
  기존 자동화 파이프라인(바이낸스 REST·FRED CSV·blockchain.info 등 전부 무인증)과 다른 유일한 예외.
  일별 해상도라 4h 진입에는 하루 6개 봉이 같은 게이트 값을 공유(당일 내 6개 봉 전부 같은 레짐).

## 예상 신호 빈도·임계값 백분위
- `gas_z>=2.0`은 정규분포 가정 시 약 2.3%(연 8~9일). 다만 가스비는 팬텐일(대형 NFT 민팅·에어드랍·
  DeFi 청산 이벤트로 급등)이 잦아 **실제 발생률이 정규 가정보다 높을 것으로 [추정]** — 1차 진단에서
  실측 백분위(2.0σ가 실제로 며칠에 해당하는지)부터 확인. 연 예상 트리거 8~20건(4h 확인까지 거친 최종
  진입은 이보다 적음, 절반 정도로 [추정]).

## 비용 감당 산술
- 4h 트레일링 스윙이라 예상 빈도(연 8~20건)에 왕복수수료 0.14%를 곱하면 연 비용 1.1~2.8%p 수준 — ATR
  배수 기반 손익폭(수 %)이 이를 웃돌면 감당 가능. gross PF가 손익분기(1.0) 근접이면 net에서 쉽게 잠식될
  빈도는 아니나, **이벤트당 R이 충분히 커야 함**(과거 여러 라운드에서 "gross부터 무엣지"가 최다 실패
  원인이었음을 반영해 1차 진단에서 gross PF부터 확인).

## 사전 폐기조건 (⚠️사후 변경 금지)
1. OOS gross PF(R) < 1.05 또는 t 비유의(|t|<1.96) → FAIL(비용 이전부터 무엣지).
2. OOS 거래 건수 < 15건 → 판단불가.
3. **판정 단위**: 트레이드 단위. 다만 가스비 급등이 여러 날 연속되는 클러스터일 수 있어(같은 이벤트가
   30일 롤링 z-score를 며칠 연속 넘김) **캘린더일 단위 de-clustering도 병행**하고, 트레이드 단위와
   캘린더일 단위 결과가 크게 어긋나면(부호 반전 등) 캘린더일 기준을 우선.
4. `gas_z` 방향(EMA 위/아래로 롱/숏 나누는 설계)이 **방향반전 대조군(EMA 조건 없이 무조건 롱만/숏만)**
   대비 유의하게 우수하지 않으면 → EMA 방향필터 자체가 무의미하다고 판정, 게이트 없는 순수 가스비 극단
   양방향 대조군과 비교해 재평가.

## 전제의 내적 일관성 자문
- **핵심 위험**: 가스비는 ETH 가격과 **동시에 함께 움직이는 경향**(가격 상승기에 거래·DeFi 활동 자체가
  증가해 가스비도 오르는 경우가 많음) — 이 경우 `gas_z` 극단이 사실상 "ETH가 이미 크게 오르고 있었다"의
  재확인일 뿐 독립 정보가 아닐 위험. 반대로 청산 캐스케이드·패닉 매도 시에도 온체인 활동(청산 트랜잭션)이
  급증해 가스비가 오를 수 있어 **가스비 급등 자체는 방향 중립적 "활동 급증" 신호**라는 것이 이 스펙의
  핵심 전제 — 이 전제가 맞는지(가스비 급등이 실제로 상승/하락 양쪽에서 고르게 관측되는지) 1차 진단에서
  가스비 극단 시점의 ETH 동시 수익률 분포(양/음 비율)를 반드시 실측.

## 동어반복 점검
- `gas_z`와 ETH 자체의 24h 변동성(realized vol) 및 거래량 z-score의 상관을 **전체구간 + 트리거 시점
  한정** 둘 다 실측 — 상관이 극히 높으면(|r|>=0.7) 이 스펙은 기존 변동성/거래량 계열 스펙(예: 여러 breadth·
  volatility 게이트)의 재탕에 가까울 위험.

## 셔플/대조군
- **정보원 무력화**: 가스비 시계열을 시점 셔플한 무작위판 vs 원본 비교(가스비의 "타이밍 정보"가 실제로
  가치 있는지). 100회 반복.
- **조건제거판**: `ema20` 방향필터 없이 `gas_z` 극단만으로 무조건 롱 진입하는 버전과 무조건 숏 진입하는
  버전을 별도 병행(어느 한쪽이 방향필터판보다 우수하면 방향필터가 오히려 해로운 것).
- ⚠️승률 고정 셔플은 항등식 함정 회피를 위해 **트리거 시점 자체를 무작위화**하는 방식 채택(승/패 풀
  복원추출 금지).

## 스카우트 메모
- **강점**: 이더리움 네트워크 자체의 활동량을 직접 보는 완전히 새로운 데이터 축(기존 437개 중 온체인
  네트워크 지표는 해시레이트·난이도 재조정(BTC)뿐, 이더리움 고유 지표는 전무). ETH 전용이라 우리 유니버스
  중 단일종목에만 적용되는 명확한 한계가 있으나, 그만큼 가설도 명확함.
- **의심점**: ①API 키 발급이라는 신규 인프라 부담(무료지만 기존 완전 무인증 패턴과 다름) ②동시성(가격과
  가스비가 함께 움직임) 문제로 독립 정보가 아닐 위험이 가장 큼 ③가스비 자체가 EIP-1559 이후(2021-08~)
  base fee 메커니즘으로 산정 방식이 바뀌어 **2021-08 전후로 시계열 성격이 달라질 수 있음** — 1차 진단에서
  EIP-1559 이전 구간을 포함할지 별도 검토 필요.
- **우리 슬리브와의 관계**: 라이브 `scalp15m`과 시간축·종목(ETH 단일)이 달라 대체관계 아님. 신규 API 키
  인프라 부담 때문에 **백테스트 우선순위는 중간 이하**로 권고(FRED·blockchain.info 기반 스펙보다 후순위).
