# [단타] 스팟-선물 거래대금 비율(레버리지 참여도) 극단 역추세

- **출처**: https://www.tradingview.com/script/uF3K4pHZ/ (TradingView, "BTC Spot/Futures Volume Ratio" 지표, 작성자 wzkkzw12345 — **WebFetch로 원문 확인**: "Shows the ratio between the spot trading volume versus futures trading volume for Bitcoin", 해석 예시로 "가격 고점에서 비율이 점진적 하락 시 분배(distribution) 단계 종료 신호", "가격 저점에서 비율이 최저치일 때 바닥 신호" 서술. 코드 상세·정확한 계산식·백테스트 수치는 페이지에 없음(오픈소스 코드 열람 필요, 이번 세션에선 미열람)). 보조 개념 근거 — https://www.coinapi.io/blog/crypto-futures-explained-understanding-perpetual-contracts (OI·거래량·펀딩을 함께 봐야 한다는 일반론).
  - **원문에 없는 부분은 스카우트가 자체 설계**: TradingView 지표는 해석 방향(고점+비율하락=분배, 저점+비율최저=바닥)만 제시하고 구체적 임계값·진입/청산·손절 규칙이 전혀 없어, 본 스펙은 그 컨셉을 코딩 가능한 규칙으로 구체화한 것임을 명시.
- **참여지표**: TradingView 지표 자체의 좋아요/조회수는 페이지에서 확인 안 됨(-). "스팟 대비 선물 거래량 비율로 레버리지 참여도를 읽는다"는 개념은 OI·펀딩과 함께 크립토 파생상품 교육 콘텐츠(Coinglass, Coinapi 등)에서 반복 언급되는 표준적 프레임.
- **백테스트 근거**: **없음(개념 기반, 스카우트가 규칙 구체화)**. 정량 수치 지어내지 않음.
- **⚠️ 예상 신호빈도 사전 명시**: 1h 해상도로 비율을 계산해 30일(720봉) 롤링 백분위 상/하위 10%(즉 시간의 20%)를 "극단"으로 잡고, 여기에 "가격이 최근 20봉 고/저 근접"이라는 2차 조건을 AND로 거는 구조. 두 조건이 완전 독립이면 대략 시간의 2%(연 175봉 근방, 종목당 월 15회 안팎) 수준을 기대하지만, **아래 내적 일관성 검토에서 지적하듯 두 조건이 서로 독립이 아닐 가능성이 높아 실제 빈도는 이 추정과 크게 어긋날 수 있음** — 백테스터는 반드시 실측 트리거 횟수를 먼저 보고할 것.
- **⚠️ 전제의 내적 일관성 사전 검토(실측 대조 필수)**: (1) 바이낸스 BTC/ETH 등 메이저의 **선물 거래대금은 통상 스팟보다 5~20배 크다**(구조적 기저 불균형) — 절대 비율이 아니라 반드시 **롤링 백분위**로 정규화해야 하며, 그렇지 않으면 상시 "선물 우위" 상태를 매번 "극단"으로 오인하는 구 z-score 데미닝 누락과 동일한 함정에 빠진다. (2) 가격 돌파/급등락 국면은 통상 스팟·선물 거래량이 **함께** 급증하는 경우가 많아 비율 자체는 오히려 완만할 수 있음 — "선물만 튀고 스팟은 안 튀는" 진짜 디커플링 구간이 가설만큼 자주 나오지 않을 위험이 있다(체결건수-레인지스퀴즈 상호배타 사례와 유사한 함정 가능성). 백테스터는 스팟거래대금과 선물거래대금의 상관계수를 먼저 실측 보고할 것.
- **타임프레임**: 1h 신호 / 4h 확인.
- **시장/대상**: BTC·ETH·BNB(스팟 데이터가 충분히 유동적인 메이저 한정 — 선물 전용 알트는 스팟 자체가 없어 적용 불가).

## 진입 규칙
- **스팟 거래대금**: `data.binance.vision` 현물 klines(quote_asset_volume, 1h) — 기존 인프라(현물 미러)로 확보 가능.
- **선물 거래대금**: 동일 심볼 선물 klines(quote_asset_volume, 1h) — 기존 확보.
- **비율**: `ratio[i] = spot_quote_vol[i] / futures_quote_vol[i]`.
- **정규화**: `ratio_pctile[i] = percentile_rank(ratio[i], window=720봉(30일))` (z-score 대신 **비모수 롤링 백분위** 사용 — 데미닝 누락 함정 회피).
- **숏(레버리지 주도 돌파 페이드)**: `ratio_pctile <= 10`(선물이 스팟 대비 이례적으로 압도) **AND** 종가가 최근 `price_lookback`=20봉 고가 갱신 → 레버리지 투기가 주도한 상승으로 판단, 되돌림 기대 숏.
- **롱(스팟 주도 저점 매수 페이드)**: `ratio_pctile >= 90`(스팟이 이례적으로 우위, 즉 레버리지 대비 현물 실수요 상대적 강세) **AND** 종가가 최근 20봉 저가 갱신 → 패닉성 급락 속 현물 매수세 유입으로 판단, 반등 기대 롱.

## 청산 규칙
- 익절: R:R 1.8:1 고정, 또는 `ratio_pctile`이 중립대(40~60)로 복귀 시 청산.
- 손절: 신호봉 반대 극값(숏=신호봉 고가, 롱=신호봉 저가) 또는 진입가 ∓ ATR(14,1h)×1.2.
- 시간 청산: 최대 보유 `max_hold_bars`=12봉(1h 기준 12시간) 초과 시 강제 청산.

## 파라미터
- ratio_window=720봉(30일) (범위 480~1440)
- extreme_low_pctile=10 (범위 5~15), extreme_high_pctile=90 (범위 85~95)
- price_lookback=20봉 (범위 15~30)
- max_hold_bars=12 (범위 8~24)
- stop_atr_mult=1.2 (범위 1.0~2.0)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 스팟 klines quote_asset_volume, 선물 klines quote_asset_volume, 롤링 백분위 계산, Donchian(20) 고저.
- 주의: **스팟 데이터는 `data-api.binance.vision`(현물 미러) 또는 `data.binance.vision/data/spot/...` 덤프로 충족.** 단 현물 미러는 CLAUDE.md에 이미 기록된 대로 **선물전용 알트가 없음** — 이 스펙은 애초에 스팟·선물이 모두 상장된 메이저 한정이라 문제 없음. 오더북/틱/청산 불필요.

## 스카우트 메모
- **강점**: 스팟-선물 거래대금 비율은 기존 300개 스펙 어디에도 없는 신규 데이터 조합(거래대금 자체가 아니라 "같은 코인의 두 시장 간 거래대금 비율")이며, TradingView에 실제 배포된 지표로 커뮤니티에서 참조되는 프레임. z-score 대신 백분위 정규화를 채택해 최근 반복 지적된 데미닝 함정을 스펙 단계에서 회피.
- **의심점**: 원문에 백테스트가 전혀 없어 순수 자체 설계이고, 위에서 지적한 "스팟·선물 거래량 동시 급증" 내적 일관성 문제가 실측에서 드러나면(과거 체결건수-스퀴즈 사례처럼) 신호빈도가 가설의 1/수십로 붕괴할 위험이 있다 — 백테스터는 반드시 스팟-선물 거래량 상관계수와 실제 트리거 수를 최우선 보고할 것.
- **우리 슬리브와의 관계**: 기존 라이브 `scalp15m`(볼린저 이탈+거래량+OI)과 데이터축이 다름(거래량 절대치가 아닌 시장간 비율) — 대체보다는 신규 시그널원 후보.
