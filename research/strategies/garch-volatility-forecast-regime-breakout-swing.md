# [스윙] GARCH(1,1) 변동성 예측 기반 레짐 브레이크아웃/포지션사이징

- **출처**: https://medium.com/@yavuzakbay/forecasting-crypto-volatility-with-garch-models-6a67822d1273 (GARCH 크립토 적용 개괄), https://github.com/chibui191/bitcoin_volatility_forecasting (GARCH·LSTM 비트코인 변동성 예측 GitHub), https://arxiv.org/pdf/2010.07402 ("A Horserace of Volatility Models for Cryptocurrency") — 학술 연구 다수가 "GARCH가 크립토 변동성 예측에서 실현변동성 대비 예측력이 우수하다"고 보고. WebSearch로 확인, 개별 논문 원문 정량 수치는 세션 내 WebFetch 대조 미완료.
- **참여지표**: - (학술 연구·오픈소스 코드 기반, SNS 참여지표 미집계).
- **백테스트 근거**: **원 논문들은 "GARCH 변동성예측 vs 옵션 내재변동성" 비교 및 "포지션 사이징에 변동성 예측 반영 시 샤프비율 개선" 같은 정성적 결론을 보고**하나, 이번 세션에서 특정 논문의 정량 수치(수익률·승률·PF)를 원문 WebFetch로 확정 대조하지 못했으므로 **"정량 수치 원문 미확인"으로 정직히 표기**. 이 스펙은 **GARCH 모델 자체를 매매규칙에 이식한 신규 응용**이며 우리 프레임워크에서 처음부터 백테스트 필요.
- **타임프레임**: 1d 수익률로 GARCH 적합 → 4h~1d 신호로 브레이크아웃 진입
- **시장/대상**: BTC·ETH·시총상위 알트 무기한

## 진입 규칙
- **모델**: 일간 로그수익률 `r(t) = ln(Close(t)/Close(t-1))`에 **GARCH(1,1)**을 적합: `σ²(t) = ω + α·r(t-1)² + β·σ²(t-1)`. 롤링 윈도우(예 500일)로 매일(또는 매주) 재적합해 다음 1일 조건부 변동성 `σ_forecast(t+1)`을 산출.
- **변동성 레짐 판정**: `vol_ratio(t) = σ_forecast(t+1) / realized_vol_20d(t)` (GARCH 예측치가 최근 실현변동성보다 얼마나 높은/낮은지). `vol_ratio > 1.3` = **변동성 확장 예고**(GARCH가 향후 변동성 급증을 예측), `vol_ratio < 0.7` = **변동성 수축 예고**(스퀴즈 예상).
- 롱(변동성 확장 예고 + 상방 돌파): `vol_ratio(t) > 1.3` **AND** 당일 종가가 최근 20일 최고가 상향 돌파 → 롱 진입(모델이 "변동성 폭발 임박"을 예측한 시점에 실제 상방 브레이크아웃이 확인되면 진입, 가짜돌파 필터링 목적).
- 숏: 동일 조건에서 20일 최저가 하향 돌파 시 숏.
- 수축 예고(`vol_ratio < 0.7`) 구간은 **신규 진입 보류**(스퀴즈 중 방향성 베팅 회피, 대기).

## 청산 규칙
- 익절: 정액 목표 없음 — ATR 트레일링(ATR(14)×2.0)으로 추세 지속 시 보유.
- 손절: 진입 시점 ATR(14)×1.5 또는 최근 스윙 저점/고점.
- 시간/조건 청산: `vol_ratio`가 다시 1.0 아래로 하락(GARCH 예측 변동성이 실현변동성 이하로 정상화)하면 추세 동력 소멸로 간주해 청산 검토.

## 파라미터
- garch_p=1, garch_q=1 (표준 GARCH(1,1), 확장 시 EGARCH/GJR-GARCH 등 비대칭모델 고려 가능)
- fit_window=500일 (범위 250~750일, 재적합 주기 매주 1회 권장 — 매일 재적합은 연산비용 과다)
- realized_vol_window=20일
- vol_ratio_expand_th=1.3 (범위 1.2~1.5), vol_ratio_contract_th=0.7 (범위 0.6~0.8)
- breakout_lookback=20일 (범위 15~30)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 일봉 종가(로그수익률)만 있으면 GARCH 적합 가능 — 바이낸스 REST klines로 충분. 오더북/틱 불필요.
- 난이도: **중간~높음**. 지표 계산 자체는 데이터만 있으면 되지만, **GARCH 모델 적합(MLE 최적화)이 다른 스펙 대비 연산비용이 높고**(`arch` 파이썬 패키지 필요), 백테스트 시 **매 재적합 시점마다 그 시점까지의 데이터만 사용(룩어헤드 금지)**해야 해 구현 난이도가 높음. 재적합 주기·수렴 실패 예외처리 등 엔지니어링 부담 있음.
- 주의: GARCH는 모델 기반 예측이라 **모델 리스크**(파라미터 불안정, 급변 국면에서 재적합 지연)가 존재 — 단순 realized-vol(ATR/Parkinson) 대비 실익이 있는지 반드시 A/B 비교 필요.

## 스카우트 메모
- **강점**: 기존 변동성 계열(`parkinson-volatility-regime-breakout-swing`, `chaikin-volatility-contraction-expansion-breakout-swing`, `larry-williams-adaptive-noise-ratio-volatility-breakout-swing`, `atr-regime-grid-dca-range-scalp`)은 모두 **과거 실현변동성을 그대로 쓰는 후행지표**인 반면, GARCH는 **조건부 변동성을 앞으로 예측하는 선행(forecasting) 모델**이라 메커니즘이 근본적으로 다름. "변동성이 커질 것"을 미리 예측해 돌파 신호의 신뢰도를 높이는 것이 이론적 장점.
- **의심점**: (1) 정량 백테스트 근거를 원문 대조하지 못해 실제 엣지 미확인. (2) 모델 적합 비용·복잡도가 높아 다른 스펙 대비 과최적화·버그 리스크가 큼(특히 룩어헤드 방지가 까다로움). (3) GARCH 예측이 단순 20일 realized vol 대비 유의미하게 나은지 학계에서도 의견이 갈림("혼재된" 결과 다수) — 실익이 미미할 가능성 배제 못함.
- **우리 슬리브와의 관계**: 변동성 레짐 필터 계열의 **고도화 버전**(대체 후보) — 기존 ATR/Parkinson 기반 변동성 필터와 병렬 백테스트해 GARCH가 실제로 개선을 주는지 확인 후에만 채택 가치. 구현 난이도가 높아 **우선순위는 낮게** 잡는 것이 합리적(다른 저난이도 후보 먼저 검증 권장).
