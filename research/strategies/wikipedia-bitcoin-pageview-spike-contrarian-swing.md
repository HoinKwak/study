# [스윙] 위키피디아 'Bitcoin' 문서 일일 조회수 급증 컨트래리언

- **출처**: 데이터 소스 — Wikimedia REST API `https://wikimedia.org/api/rest_v1/metrics/pageviews/
  per-article/en.wikipedia/all-access/all-agents/Bitcoin/daily/{start}/{end}`(무료, 인증불요).
  2026-08-21 Bash `curl`로 직접 확인: 2015-07-01(API 최초 제공 시점)부터 2026-08(최신)까지 일별
  조회수(`views`) 정상 반환(예: 2015-07-01 13,137회, 2026-08-01 4,241회) — 우리 백테스트 구간
  (2020~2026 선물 데이터)을 전 구간 커버.
  개념 배경 — "리테일 대중의 관심 급증(구글 트렌드·위키피디아 조회수 등)은 종종 사이클 말미의
  과열/FOMO를 반영해 역발상 매도 신호가 된다"는 명제는 크립토·주식 시장 양쪽에서 널리 논의되는
  통설(구글 트렌드 "bitcoin" 검색량과 가격 정점의 동행 관계는 2017·2021 사이클에서 다수 매체가
  사후적으로 언급)이나, **이 정확한 "위키피디아 일일 조회수 z-score 급증 컨트래리언" 규칙을 그대로
  백테스트한 외부 자료는 찾지 못함 — 스카우트 자체 설계, 지어내지 않음**. 구글 트렌드 대신 위키
  피디아를 택한 이유: 구글 트렌드는 비공식 라이브러리(pytrends)에 의존해 접근 신뢰성이 낮고 주간
  해상도·상대지수(0~100 정규화, 절대량 아님)라 장기 백테스트에 부적합한 반면, 위키피디아 API는
  공식 REST(JSON, 인증불요)로 **절대 조회수**를 일별 해상도로 안정적으로 제공한다(2026-08-21 세션
  기준 기존 402개 스펙에 `위키피디아|wikipedia|pageview|구글 트렌드|google trends` 키워드 0건 확인
  — 완전 신규 데이터축).
- **참여지표**: - (온라인 관심도 프록시 데이터, SNS 참여지표 미집계). "리테일 관심 지표의 역발상
  활용"이라는 프레임 자체는 업계에서 자주 언급되나 정확한 정량 승률·PF 원문은 찾지 못해 인용 안 함.
- **백테스트 근거**: **없음(자체 설계, 정직히 표기)**. 채택 전 자체 백테스트 필수.
- **타임프레임**: 위키피디아 조회수 1d(UTC 00:00 기준 일별 집계) / BTC 신호·확인 1d, 트레일링 4h.
- **시장/대상**: BTC 무기한 단일종목(조회수는 'Bitcoin' 문서 기준이라 BTC 고유 — 확장 시 별도 문서
  'Ethereum' 등으로 ETH 검증 가능하나 1차는 BTC로 한정).

## 핵심 아이디어
위키피디아 'Bitcoin' 문서는 뉴스에 노출된 초보 투자자·일반 대중이 "비트코인이 뭐지" 하고 검색해
유입되는 대표적 관문 페이지다. 조회수가 평소 대비 급격히 튀어오르는 날은 통상 가격이 이미 크게
움직인 뒤(미디어 보도 확산 시차 포함) 대중의 관심이 정점에 달한 시점과 겹칠 가능성이 높다 — 이런
"관심 정점"은 단기 과열의 방증으로 보고 역발상(컨트래리언) 진입한다.

## 예상 신호 빈도
- 일별 z-score 임계 초과(뒤 규칙 참조)를 [추정] 조회수 분포 특성상 연 15~30회 수준으로 예상(뉴스성
  스파이크는 정상분포보다 두꺼운 꼬리를 가질 것으로 예상되어 단순 3σ 임계보다 빈번할 가능성 있음).
  가격 조건(최근 급등/급락 동반)까지 결합하면 [추정] 연 8~15건으로 좁혀질 것으로 예상.

## 비용 감당 산술
- 예상 빈도 연 8~15건 × 왕복수수료 0.14% = 연 총비용 부담 1.12~2.1%p로 낮음 — 저빈도·스윙 보유라
  수수료가 결론을 좌우할 가능성은 낮으나, 트레이드당 기대수익이 작으면(예: 평균 1~2%대) 여전히
  유의미한 잠식이 될 수 있어 net PF 기준 평가가 필요.

## 전제의 내적 일관성 사전 검토
- 전제: "조회수 급증 = 가격이 이미 크게 움직인 뒤"라는 가정이 실제로 성립하는지(즉 조회수 급증이
  가격 급등/급락에 **후행**하는지) 먼저 확인해야 한다 — 만약 조회수 급증이 오히려 가격 급등보다
  **선행**한다면(신규 자금 유입의 초기 신호), 컨트래리언이 아니라 모멘텀 방향으로 거래하는 것이
  맞을 수 있다. 백테스터는 1차 진단으로 조회수 z-score 스파이크 시점과 BTC 5일 누적수익률의 **시차
  교차상관(lag -10~+10일)**을 계산해, 선행/후행 관계를 먼저 확정하고 그 결과에 따라 방향(컨트래리언
  vs 모멘텀)을 조정할 것 — 아래 진입 규칙은 "후행" 가정 하의 기본안이며, 선행으로 판명되면 대조군 B
  (방향반전)를 본 채택안으로 승격 검토.
- ⚠️ **뉴스 이벤트 오염 우려**: 조회수 급증이 가격과 무관한 순수 뉴스 이벤트(예: 규제 발표, 유명인
  발언, 해킹 사고)에 기인할 수 있어, 가격 변동을 동반하지 않는 조회수 스파이크(예: 정책 뉴스이나
  가격은 안 움직인 날)는 신호에서 자연히 걸러지도록 **가격 조건을 반드시 결합**한다(아래 진입 규칙).

## 동어반복 점검
- 조회수 급증과 BTC 자체의 실현변동성 급증(예: `parkinson-volatility-regime-breakout-swing.md`류)이
  단순히 "둘 다 큰 뉴스가 있는 날 함께 튄다"는 이유로 사실상 동일 정보일 위험이 있다 — 1차 진단에서
  조회수 z-score와 BTC 24h 실현변동성 z-score의 상관을 계산하고, 상관이 높더라도(뉴스일에 둘 다
  튀는 것은 자연스러움) **조회수 스파이크 중 가격 변동성이 평범한 날(변동성 z<1)만 골라낸 부분집합**
  이 여전히 유효한 신호를 내는지로 독립성을 판별한다(변동성과 무관하게 "관심"만 튄 날이 정보를
  담고 있는지).

## 종목 간 신호 상관 사전 예상
- BTC 단일종목 검증. 위키피디아 'Bitcoin' 문서 조회수는 크립토 시장 전반의 관심도를 대리하므로
  확장 시 알트코인에도 높은 신호 상관(0.7+)을 가질 것으로 예상 — 1차는 BTC 단일로 한정해 다각화
  착시를 피한다.

## 정규화 게이트 논증
- 조회수는 위키피디아 전체 트래픽 성장(인터넷 이용자 수 증가 등) 때문에 장기 구조적 우상향 추세를
  가질 수 있어, 고정 절대 임계값 대신 **트레일링 180일 롤링 평균·표준편차 기반 z-score**로 정규화한다
  (`pv_z(t) = (views(t) - rolling_mean_180(views)) / rolling_std_180(views)`). 평균 차감을 반드시
  포함해 데미닝 누락 함정(과거 인덱스가격 스냅백 사례)을 피한다.

## 수익 인과 경로
- 조회수 급증(대중 관심 정점)이 가격 급등에 후행한다면, 이는 "이미 오른 뒤 뒤늦게 진입하려는 리테일
  자금 유입의 정점"을 반영하며 통상 이런 정점 이후 단기 되돌림(과매수 해소)이 뒤따른다는 가설 —
  전통적 "생불이 신문 1면에 나오면 팔아라" 류의 컨트래리언 심리와 동일한 논리를 정량 데이터로
  대체한 것.

## 라이브 실행 가능성
- Wikimedia API는 무료·인증불요로 실시간 조회 가능하나 **본 봇 라이브 인프라는 현재 위키피디아
  데이터를 보유하지 않음 — 신규 fetch 파이프라인 구축 필요**(GET 단순 응답, 구현 난이도 낮음).
  API 공표 지연 확인 필요 — Wikimedia pageviews는 통상 **집계일 익일(D+1)**에 확정 게시되는 것으로
  알려져 있으므로(공식 문서 fetch로 재확인 권고), 백테스트에서도 신호일 종가가 아니라 **D+1 시가부터**
  유효한 것으로 보수적으로 처리한다.

## 진입 규칙
- `pv_z(t) = (views(t) - rolling_mean_180(views)) / rolling_std_180(views)`.
- **스파이크 판정**: `pv_z(t) >= 3.0`.
- **가격 조건(결합, 롱 컨트래리언 = 급락 후 반등 베팅이 아니라 급등 후 눌림 베팅)**: 스파이크 발생
  직전 5일 BTC 누적수익률 `price_roc5 >= +8%`(스파이크가 급등과 동반) **AND** RSI(14,1d) >= 70
  (과매수 확인) → **숏**(과열 되돌림 베팅).
- **대칭(급락 후 항복 관심 급증 → 반등 베팅)**: `price_roc5 <= -8%` **AND** RSI(14,1d) <= 30
  (과매도 확인) → **롱**.
- D+1 지연 반영: 신호일 종가가 아니라 익일 시가에 진입.

## 청산 규칙
- 익절: R:R `rr_target`=1.5 도달 또는 RSI(14,1d)가 50 중립선 복귀.
- 손절: 진입가 ∓ ATR(14,1d)×1.5.
- 시간 청산: `max_hold=10`일(단기 과열 해소 베팅이라 짧게 제한).

## 파라미터
- rolling_window=180일 (범위 120~270), pv_z_th=3.0 (범위 2.5~4.0)
- price_roc_th=8% (범위 5~12%), rsi_th=70/30 (범위 65~75 / 25~35)
- rr_target=1.5 (범위 1.2~2.0), stop_atr_mult=1.5 (범위 1.0~2.0), max_hold=10일 (범위 5~15)

## 핵심 대조군 정의
- **대조군 A(선후행 검증, 최우선)**: 위 전제 검토에서 선행 관계로 판명되면 방향을 반대로(스파이크+
  급등 동반 → 롱, 모멘텀 추종)로 실행 — 어느 방향이 실제로 유효한지 분리.
- **대조군 B(게이트 없음)**: 조회수 조건 없이 순수 RSI 과매수/과매도+5일 수익률 조건만으로 실행 —
  조회수 정보의 부가가치 분리.
- **대조군 C(변동성 통제)**: 조회수 스파이크를 BTC 실현변동성 z-score 스파이크로 교체 — 동어반복
  점검과 연동, 두 지표가 구분되는 성과를 내는지 확인.
- **대조군 D(지연 없음)**: D+1 지연을 무시하고 즉시 진입 — 라이브 실행 가능성 판단 자료.

## 사전 폐기 조건
- (a) 결합 트리거가 연 3건 미만이면 표본부족 판단불가로 조기 종결.
- (b) 무비용(fee=0·slippage=0) 시뮬 OOS gross PF < 1.0이면 폐기.
- (c) 대조군 B(게이트 없음) 대비 개선이 없으면 조회수 정보의 부가가치 부재로 폐기.
- (d) 대조군 A(방향반전)가 뚜렷이 우수하면 "컨트래리언이 아니라 모멘텀"으로 라벨을 뒤집어 재평가
  (자동 폐기 아닌 방향 재판정).

## 코딩 난이도 / 데이터 요구
- 필요한 지표: Wikimedia pageviews API(신규 파이프라인), BTCUSDT 1d klines, RSI14, ATR14(1d).
- 주의: **바이낸스 밖 외부 데이터** — 신규 fetch 구축 필요(무료·인증불요·JSON GET). 문서명 변경
  이력(예: 문서가 리다이렉트·병합된 적 있는지)이 있는지 사전 확인 권고 — 'Bitcoin'은 안정적인
  문서명으로 판단되나 백테스터가 착수 시 최종 확인.

## 스카우트 메모
- **강점**: 완전 신규 데이터축(리테일 관심도 프록시)이며 API 신뢰성이 mempool.space·FRED와 마찬가지로
  높음을 이번 세션에 직접 확인(구글 트렌드의 비공식 라이브러리 의존 문제를 회피). 컨트래리언 논리가
  명확하고 코딩 가능한 규칙으로 환원됨.
- **의심점**: 선후행 관계가 사전 검토 대상이라 방향(컨트래리언 vs 모멘텀) 자체가 백테스트 전에는
  확정되지 않음 — 스펙 단계에서 두 방향 모두를 명시해 어느 쪽이 실증되든 즉시 판정 가능하도록
  설계함. 뉴스 이벤트 오염(가격과 무관한 스파이크) 가능성도 완전히 배제하지 못함.
- **우리 슬리브와의 관계**: 채택 시 저빈도 이벤트드리븐 스윙 슬리브 후보. 기존 라이브 15m 스캘프와
  경쟁하지 않음.
