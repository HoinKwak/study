- **출처**: https://www.coinglass.com/learn/how-to-use-liqmap-to-assist-trading-en (CoinGlass 공식, 청산 히트맵 활용법) /
  https://docs.coinglass.com/reference/liquidation-heatmap (CoinGlass API 문서, 레버리지 티어 모델) /
  https://zipmex.com/blog/what-is-a-liquidation-heatmap/ (Zipmex, 히트맵 계산 방식) /
  https://www.bydfi.com/en/cointalk/coinglass-liquidation-heatmap (BYDFi, 청산 자석 개념 설명)
- **참여지표**: 없음(거래소·데이터업체 공식 교육 콘텐츠, 개별 SNS 조회수 미집계) — 다만 CoinGlass 청산 히트맵은 크립토 파생 트레이딩 커뮤니티에서 **가장 널리 참조되는 시각화 도구 중 하나**(X·유튜브에서 스크린샷 인용 빈도가 매우 높음, 정량 집계는 못 함).
- **백테스트 근거**: **없음(개념 기반, 본 스펙 저자가 규칙 구체화)**. 원문들은 "청산 클러스터=가격 자석, 밀집 구간에 도달하면 캐스케이드 가속" 이라는 정성적 메커니즘만 설명하고, "레버리지는 10x/25x/50x/100x 티어 가정, 실제 대비 1~3% 오차"라는 방법론적 한계도 명시. **정량 수치(임계값 등)는 전부 저자 임의 설정** — 채택 전 자체 백테스트 필수.
- **타임프레임**: 15m 신호 / 1h 확인
- **시장/대상**: BTC·ETH·시총상위 알트 무기한(OI 데이터가 안정적인 유동성 종목)

## 진입 규칙
- **합성 청산가 추정**: 최근 `oi_window`(예 15m×48=12시간) 동안의 OI 증분(`ΔOI_bucket` = 각 15m봉의 OI 변화량)을 그 봉의 종가에 귀속시켜 "가격대별 신규 레버리지 유입량" 시계열을 만든다. 각 유입분에 대해 공통 레버리지 티어(10x, 25x, 50x, 100x)를 가정해 롱/숏 청산가를 계산: 롱 청산가 = 유입 시점 종가 × (1 − 1/N), 숏 청산가 = 종가 × (1 + 1/N).
- **클러스터 식별**: 계산된 청산가들을 가격 구간 `cluster_bin_pct`(예 0.5%)로 비닝(binning) → 특정 구간에 몰린 청산가 개수(가중치=해당 유입 OI 크기)가 상위 `cluster_top_pct`(예 상위 15%)에 드는 구간을 "밀집 클러스터"로 표시.
- **롱(상방 돌파-캐스케이드 추종)**: 현재가가 **상단 숏 청산 클러스터**(현재가보다 위, 최근접) 진입 `approach_pct`(예 0.3%) 이내로 접근 + 거래량 급증(직전 20봉 평균 대비 `vol_spike_mult`=2.0배 이상) + 15m 종가가 클러스터 상단을 돌파 → **롱**(숏 청산 캐스케이드로 인한 가속 상승에 편승).
- **숏(하방 돌파-캐스케이드 추종)**: 대칭 — **하단 롱 청산 클러스터**에 접근 + 거래량 급증 + 종가가 클러스터 하단 이탈 → **숏**.
- 확인(1h): 방향과 같은 부호의 OI ROC(최근 4봉, 1h 기준)가 양(+)이어야 진입(레버리지가 실제로 쌓인 구간인지 확인).

## 청산 규칙
- **익절**: 다음 상위/하위 클러스터까지, 또는 목표 R:R 2.0:1 도달 시.
- **손절**: 돌파 시작점(클러스터 진입가) 재이탈 시, 또는 −1.2×ATR(15m).
- **시간 청산**: 진입 후 `max_hold_bars`=8봉(15m×8=2시간) 내 목표 미도달 시 시간청산(캐스케이드는 보통 단기간에 소진).

## 파라미터
- oi_window=48봉(15m, 12시간) (범위 24~96)
- leverage_tiers=[10,25,50,100] (고정, CoinGlass "Model 1" 관행 참고)
- cluster_bin_pct=0.5% (범위 0.3~0.8%)
- cluster_top_pct=15% (범위 10~20%)
- approach_pct=0.3% (범위 0.2~0.5%)
- vol_spike_mult=2.0 (범위 1.5~3.0)
- rr_target=2.0 (범위 1.5~2.5)
- atr_mult_sl=1.2 (범위 1.0~1.5)
- max_hold_bars=8 (15m 기준, 범위 6~12)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: OI(미결제약정) 시계열, 거래량, ATR. 바이낸스 선물 REST `openInterestHist`(5m 최소 간격) + klines 거래량으로 계산 — **실시간 청산 스트림·오더북 불필요**(합성 추정만 사용).
- **⚠️ 데이터 주의**: 기존 OI 기반 스펙들과 동일하게 `/futures/data/openInterestHist`는 **최근 약 30일치만 제공** → 장기 백테스트는 `data.binance.vision/data/futures/um/daily/metrics/` 일별 덤프의 OI 컬럼(`sum_open_interest`)을 사용해야 함(CLAUDE.md에 정리된 fapi 우회 경로 재사용 가능).
- 난이도: 중상. OI 증분을 가격대별로 귀속시키는 로직(간단한 히스토그램)과 레버리지 티어별 청산가 계산은 산술적으로 단순하나, "합성" 데이터라 **실제 청산과의 괴리가 이 전략의 근본적 리스크**(추정치일 뿐 실체가 아님)임을 명확히 인지해야 함.

## 스카우트 메모
- **강점**: 기존 `oi-roc-price-divergence-squeeze-reversal-scalp.md`(OI 변화율-가격 다이버전스 반전)·`oi-volume-leverage-crowding-contrarian-swing.md`(LCR 크라우딩 역추세)와 데이터 소스는 같은 OI지만, 본 전략은 **"가격대별 레버리지 밀집 구조를 재구성해 그 레벨에서의 돌파-가속을 추종"**한다는 점에서 메커니즘이 명확히 다름(역추세가 아니라 **추세추종/캐스케이드 편승**). CoinGlass 청산 히트맵이라는 업계 표준 프레임을 REST로 재현 가능한 형태(합성 근사)로 구체화한 점이 신규성.
- **의심점**: 레버리지 티어 가정이 실제 포지션 분포와 다를 수 있어 클러스터 위치 오차가 클 수 있음(원문도 "1~3% 오차" 인정). 정량 백테스트 근거 전무. 기존 `donchian-oi-funding-triple-stack-breakout-scalp.md`(OI+펀딩+돈치안 돌파 스택)과 "돌파+OI 확인"이라는 상위 구조가 유사할 수 있어, 채택 시 두 신호의 상관관계를 먼저 점검해야 함.
- **우리 단타 슬리브와의 관계**: 현재 라이브 `scalp15m`(볼린저 이탈+거래량+OI 필터)과 트리거 조건(거래량 급증+15m 돌파)이 구조적으로 유사 — **레벨 정의 방식(볼린저 밴드 vs 합성 청산 클러스터)만 다른 변형**에 가까울 수 있음. 백테스트 시 scalp15m 신호와의 중복률을 반드시 확인할 것.
