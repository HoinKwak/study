# [스윙] 미결제약정/거래량 레버리지 크라우딩 비율 역추세 필터

- **출처**: https://www.gate.com/crypto-wiki/article/how-to-interpret-crypto-derivatives-market-signals-funding-rates-open-interest-and-liquidation-data-explained-20251227 (Gate Wiki, 파생상품 신호 해설) /
  보조: https://phemex.com/academy/open-interest-bitcoin-trading-2026, https://smartmoneyapi.com/resources/education/open-interest-explained
- **참여지표**: - (거래소 교육 콘텐츠, 정량 조회수 미집계)
- **백테스트 근거**: **없음(개념 기반, 본 스펙 저자가 규칙을 구체화)**. 출처들은 "OI가 크고 펀딩이 극단이면 과밀 레버리지·청산 캐스케이드 위험", "BTC 합산 OI가 $80B 넘으면 30일 내 10~20% 조정 선례"(가격·시점 특정 없는 정성적 경험칙, **자산군·거래소 합산 기준이 우리 단일거래소 데이터와 다름 — 그대로 재현 불가**) 등 정성적 서술만 제공. **정량 임계값(percentile 80/85 등)은 전부 본 스캇 저자가 백테스트 캘리브레이션용으로 임의 설정한 값**이며 원문에 없음 — 명확히 구분해 표기.
- **타임프레임**: 4h~1d (레버리지 누적은 완만하게 형성되므로 스윙 스케일이 적합)
- **시장/대상**: BTC·ETH·주요 알트 무기한 (바이낸스 단일거래소 기준 — 크로스거래소 합산 OI 아님, 원 소스의 "$80B" 등 합산 임계값과 스케일 다름에 유의)

## 진입 규칙
- 지표: **레버리지 크라우딩 비율(LCR)** = 미결제약정 명목가치(OI, USD) / 최근 24h 거래대금(Quote Volume, USD). LCR이 높을수록 "거래는 적은데 쌓인 레버리지는 큰" 과밀 상태.
- LCR의 최근 30일 롤링 백분위(percentile) 계산.
- **과밀 숏(역추세) 신호**: LCR percentile ≥ **85** + 펀딩비 ≥ **+0.03%/8h**(연환산 약 33%) 동시 충족 → 상승 추세 과열로 판단, 신고가 갱신 실패(직전 고점 대비 종가 미갱신) 시 **숏** 진입.
- **디레버리지 숏스퀴즈(역추세 롱) 신호**: LCR percentile ≤ **15** + 펀딩비 ≤ **−0.02%/8h** 동시 충족 → 과도한 숏 누적 후 청산 여력 소진 국면으로 판단, 신저가 갱신 실패 시 **롱** 진입.
- (선택) OI 자체가 최근 5봉 연속 감소 중이면(디레버리지 진행 확인) 신호 강화.

## 청산 규칙
- 익절: LCR percentile이 중립대(40~60)로 복귀하면 청산, 또는 R:R 2:1 고정 목표.
- 손절: 신호 발생 봉의 반대 극값(롱=신호봉 저가, 숏=신호봉 고가) 또는 −1.5×ATR(14).
- 시간 청산: N봉(예 10봉, 4h 기준 약 1.7일) 내 목표 미도달 시 청산(레버리지 청산 캐스케이드는 통상 수일 내 해소).

## 파라미터
- lcr_window=30d (범위 20~60d, percentile 계산 기간)
- lcr_high_pct=85 (범위 80~90), lcr_low_pct=15 (범위 10~20)
- funding_high=0.03%/8h (범위 0.02~0.05%), funding_low=-0.02%/8h (범위 -0.01~-0.04%)
- rr_target=2.0 (범위 1.5~3.0), atr_mult_sl=1.5 (범위 1.0~2.0)
- time_stop_bars=10 (범위 6~20)
- oi_decline_confirm_bars=5 (선택)

## 코딩 난이도 / 데이터 요구
- 필요한 지표: 미결제약정(OI, USD 명목가치), 24h 거래대금, 펀딩비, ATR(14). 바이낸스 선물 REST `openInterestHist`, `fundingRate`, klines volume으로 계산 가능.
- **⚠️ 데이터 주의**: 바이낸스 `/futures/data/openInterestHist` REST 엔드포인트는 **최근 약 30일치만 제공**(장기 이력 조회 불가). 장기 백테스트(수개월~수년)를 하려면 `data.binance.vision`의 별도 metrics/OI 덤프가 있는지 확인이 필요하며, 없다면 **본 전략은 최근 구간에서만 검증 가능**(전체 유니버스·장기 표본 백테스트에 제약) — 백테스트 착수 전 데이터 가용성부터 확인할 것.
- 난이도: 낮음(지표 자체는 단순 비율·백분위). 단, 위 데이터 이력 제약이 백테스트 표본 크기를 제한하는 게 실질적 난점.

## 스카우트 메모
- 강점: 기존 `oi-roc-price-divergence-squeeze-reversal-scalp`(OI 변화율 vs 가격 다이버전스)·`funding-oi-price-triple-confirm-carry-momentum-swing`(OI·펀딩·가격 방향 일치 확인)와 달리, 본 전략은 **"레버리지가 거래량 대비 얼마나 과밀한가"라는 비율(크라우딩) 자체**를 신호로 쓰는 점에서 메커니즘이 다름(방향성 ROC가 아닌 상태 기반 레짐 필터) — 개념적 신규성은 있음.
- 의심점: **정량 백테스트 근거가 전혀 없고 임계값(percentile 85/15, 펀딩 0.03%) 전부 저자 임의 설정**이라 스크리닝 규칙상 근거가 가장 약함. 데이터 이력 제약(REST 30일)으로 장기 검증 자체가 어려울 수 있어 **우선순위 최하위**로 취급 권장. 개념 검증만 하려면 최근 30일 구간에서 신호 발생 빈도부터 확인.
- 우리 단타 슬리브와의 관계: 스윙 레짐 필터로서 기존 방향성 전략(scalp15m 등)에 "레버리지 과밀 구간 회피/역이용" 오버레이로 결합 가능성은 있으나, 근거 박약 + 데이터 제약으로 **단독 전략보다 참고용/향후 재검토 대상**.
